# T-123: the new language works inside a `uw new` project folder

Status: ready
Budget: $3.00
Steps: 300

## Goal

`dialog`, `area` / `on enter`, `every`, `in menu`, `<kind> … like`, `override`, `save` compile in a
project folder made by `uw new` (with `uw.lock`), not only in patch mode (folder without uw.lock).
ROADMAP: "Proje klasöründe yeni dil".

## Known facts

- Project build: crates/uw_cli/src/build_project.rs (loads record files via
  uw_decomp::project::load, writes whole tables). Patch build: crates/uw_cli/src/build.rs
  (compiles .uw sources through uw_check → patches → uw_runtime).
- Project record files are `.uw` files whose first word is a schema kind; anything else in the
  project (an `events/*.uw` file, or any item that is not a record) is today ignored or an error — verify.

## Steps

1. In build_project, collect the non-record items from all project `.uw` files (or from
   `events/` + `lib/`), check them with the same uw_check path as patch mode, against the project's
   own records (not Native's atlas), and apply the resulting patches after the tables are written.
2. A project with no such items must build exactly as before.

## How to test

crates/uw_cli/tests/project_events_t123.rs (follow the style of tests that run `uw new` on a
fixture atlas, e.g. tests/new.rs / roundtrip.rs): a project + one `dialog` and one `every day` item
→ build output contains the dialog line and the new simple trigger; same project without them →
outputs identical to the build before this change.

## Done when

- Mixed project builds; untouched project unchanged; build and tests pass.

## Do not

- Do not change crates/uw_check/src/lib.rs internals (another task edits it) beyond a public
  entry point if one is missing. Do not touch py/uw_runtime.py.

## Stop and report if

- Project records and patch-mode checks need different atlases in a way that requires redesign.
- A test still fails after 5 steps on it.
