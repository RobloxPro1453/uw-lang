# T-104: VS Code suggests names while you type (completion)

Status: ready
Budget: $1.00
Steps: 300

## Goal

Typing in a .uw file in VS Code offers the project's names: game names (`praven`, `swadia`,
`king_harlaus`), the words from `lib/*.uw` and the project's `fns/` (`fn` names), object fields
(`player.gold`), and keywords — each with a one-line Turkish hint.

## Known facts

- Extension: editors/vscode/ (extension.js from T-101 runs `uw check --json`; no npm packages allowed,
  plain `vscode` API only).
- The CLI knows all names: names layer (names.uw / atlas game names, see crates/uw_cli/src/explain.rs and
  model.rs for how `uw explain` looks names up), lib words (crates/uw_cli/src/build.rs loads lib/ and fns/),
  object fields (uw_check, T-082/T-083).
- `uw` is on PATH or in setting `uw.path`; folder rule as in T-101 (nearest ancestor with uw.toml).

## Steps

1. New CLI command `uw words --json [folder]` (new file crates/uw_cli/src/words.rs, one line in main.rs):
   prints one JSON object per line `{"label","kind","detail"}` (kind: name|word|field|keyword). Reuse the
   existing lookups; do not copy name tables by hand.
2. extension.js: a CompletionItemProvider for `uw` that runs the command once per folder (cache, refresh on
   save of names.uw / lib / fns files) and maps kinds to CompletionItemKind.
3. Tests: crates/uw_cli/tests/words.rs (temp folder: a `fn` and a lib word appear; summary not required);
   a pure `parseWords(text)` in extension.js tested by editors/vscode/test/words.test.js with plain node.

## How to test

`cargo test --workspace`; `node editors/vscode/test/words.test.js` (if node is not available say so).

## Done when
