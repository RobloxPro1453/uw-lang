# T-021: Parser: statement blocks and flagged operation names

Status: ready
Budget: $1.50
Steps: 300

## Goal

`uw_syntax` can parse a bare statement block and the kit's flagged operation names, so the decompiler
(T-020) can print every Native block in a form that parses back.

## Known facts

- Parser: crates/uw_syntax/src/lib.rs; `parse` at the end, `block`, `stmt`, `call_after`; lexer `lex`.
- Negative ints already lex when not after a value (`lex`, `c == '-' && !prev_is_value`); string
  escapes `\"` `\` `\n` exist; a curly quote (U+201C/U+201D) ends a string.
- The checker (uw_check) looks the op name up with `atlas.op(&call.op.text)`; T-022 (parallel) teaches
  it to split `neg|eq`. You only parse.

## Steps

1. `pub fn parse_block(text: &str) -> Result<Vec<Stmt>, Diagnostic>`: the statements of a block body
   without braces, same rules as inside `{ }` (newline or `;` separated, `if`, assignments, calls).
2. Flagged call names: `neg|eq(a, b)`, `this_or_next|party_is_active(p)`, `neg|this_or_next|x(...)`
   -> `Call.op.text` = the full text `"neg|eq"`, span over all of it. Accept them as statements and as
   condition calls (`Cond::Call`). Only `neg` and `this_or_next` are allowed before `|`; anything else
   is an error E0100 with help text.
3. Escapes `“` / `”` written as `\“` and `\”` inside text, so a decompiler can keep curly
   quotes.
4. Make sure `f(-1)`, `f(72057594037927936)`, `try_begin()` and `$x = -5` parse.

## How to test

Tests in uw_syntax: `parse_block_reads_statements` (3 lines incl. an if -> 3 Stmt), `flagged_call_names`
(assert `op.text == "neg|this_or_next|eq"` and args), `flag_prefix_unknown_is_error` (`foo|eq(1,2)` ->
Err E0100), `curly_quote_escape`, `negative_and_big_ints_in_calls`.
