`fn` is now a top-level UW item whose calls are inlined at check time, so the kit only ever sees Native operations.

**Syntax (`crates/uw_syntax/src/lib.rs`)**
- `Item::Fn { name, params, body, span }` new variant; parser arm for `fn <name>(:p1, :p2) { … }` in `Parser::file`, plus a small `Parser::params` that reads the `(:p1, :p2)` list (locals only; missing `(`, a non-`:local` parameter and an unclosed `(` each get their own message). The "expected … at the top level" message now lists `fn`, and the test-only exhaustive `strip` helper has a `Fn` arm.

**Check (`crates/uw_check/src/lib.rs`)**
- `check` builds a `fns: BTreeMap<String, FnDef>` from **all** sources before the per-file loop, so a `fn` in any file is visible in every file. `Item::Fn` adds no patch.
- `Ctx::stmts`: a `Stmt::Call` whose name is a fn goes to the new `Ctx::inline` instead of `Ctx::call`.
- `Ctx::inline` checks arity, then cycle/depth (a stack of names being expanded; `FN_DEPTH = 16`), copies the body through the new pure `substituted_*` helpers (they cover `Stmt`, `Block`, `Call`, `Cond`, `Expr`, `Arg`): a `:param` becomes the call's argument, every other `:local` becomes `:x__fn<N>` with a fresh `N` per call site. The expanded block is checked with `Ctx::stmts_in`, which temporarily switches to the fn body's own source file, so inlined operations keep their `file:line` origins and body errors point at the right file. Nested calls expand recursively; `uw_lower` needed no change (temporaries are numbered per block).
- New error codes: `E0213_FN_ARITY` (wrong argument count, help shows the call shape), `E0214_FN_OP_NAME` (fn named like a kit operation), `E0215_FN_CYCLE` (cycle or chain > 16, message names the chain, e.g. `a -> b -> a`). Duplicate fn names reuse `E0202_DUPLICATE` and quote the first `file:line`. Unknown names still use E0001, and fn names are now candidates for its suggestion (a name that is itself a fn is not suggested back).
