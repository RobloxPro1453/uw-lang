# T-003: uw_atlas — load the atlas JSON and look things up

Status: ready
Budget: $0.70
Steps: 180

## Goal

Rust code can load the atlas produced by `py/atlas_dump.py` and answer: "what is `p_town_6`?",
"which entry is `itm_tutorial_spear#2`?", "is `eq` a can-fail op?". This is the data layer for
`uw explain` and name checking.

## Known facts

- Schema is documented in the docstring of `py/atlas_dump.py` (read it). Top level: `schema` (=1),
  `kit_hash`, `ops` [{name, code, line, signature, lhs, can_fail, global_lhs}], `hooks` [string],
  `ranges` [{name, value, line}], `tables` {table: {module, var, id_file, id_prefix, entries: [{index,
  name, id, dup, line, value}]}}. `name`/`id`/`id_prefix`/`id_file`/`line`/`dup` may be null.
  `value` is arbitrary JSON (keep as `serde_json::Value`). `code` can exceed i64? No: use `u64`.
- `id` is null for an entry shadowed by a later duplicate; `dup` is the 1-based occurrence for names
  that repeat, else null.
- Real-data fixture: `crates/uw_atlas/tests/fixtures/atlas_small.json` (excerpt of the real atlas:
  `p_town_6` index 26 line 82 name "Praven" in value[1]; items index 1 and 130 are `tutorial_spear`
  dup 1 and 2, index 1 has id null; ops incl. `eq`, `call_script`, `party_relocate_near_party`).
- Crates allowed: `serde`, `serde_json` (MIT/Apache).

## Steps

1. Types mirroring the schema; `Atlas::from_path`, `Atlas::from_str`; reject `schema != 1` with an error.
2. Lookups: `op(name) -> Option<&Op>`; `entry_by_id(id: &str) -> Option<(&str /*table*/, &Entry)>`
   that also accepts `id#n` (n = dup occurrence; plain id resolves to the entry whose `id` field
   matches); `entries_named(table, name)`; `is_hook(name)`. Build hash maps once in the loader.
3. `all_ids()` iterator (for did-you-mean later).

## How to test

Integration tests in `crates/uw_atlas/tests/` using the fixture: `p_town_6` -> table "parties",
index 26, line 82; `itm_tutorial_spear` -> index 130; `itm_tutorial_spear#1` -> index 1;
`itm_tutorial_spear#3` -> None; `op("eq").can_fail == true`, `op("call_script").can_fail == false`;
schema 2 rejected. Check expected values against the fixture file itself before asserting them.

## Done when

- Build and tests pass.

## Do not

- Edit the fixture or `py/`. Touch other crates or docs.

## Stop and report if

- The fixture contradicts these facts.
