Core bug (report only, not fixed): every animations atlas value is a Python list, dumped as {"list": ["stand", 0, …, [3.0, "anim_human", …], …]}. print unwraps the wrapper via record_values (records.rs:153-159), but parse always rebuilds a JSON array (records.rs:298 `Ok((id, Json::Array(...)))`), and Schema has no container field (records.rs:109-118). So the {"list": …} wrapper is dropped and roundtrip_table's `value == entry.value` can never hold. YON2-KARAR.md:37 (§2.1) requires exactly that list/tuple distinction. No schema can express it: I confirmed with a temporary diagnostic (removed before finishing) that parse(print(entry)) equals the record's unwrapped list for all 670 records, so names, values, nested lists/tuples and the field_<n> tail are all correct — only the container is lost. The fix needs the shared core to carry a container kind on the schema (e.g. container = "list" | "tuple") and have parse return Value::List for list tables; print already handles both shapes.
