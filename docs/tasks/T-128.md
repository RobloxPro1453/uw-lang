# T-128: uw_start: troop operations

Status: ready
Budget: $3.00
Steps: 300

## Goal

The dry run models troop operations Native's game_start uses (faction, type, age, attributes, skills, level, items), so the start snapshot knows lords' and companions' factions and stats.

## Known facts

- Crate `crates/uw_start` runs Native's `script_game_start` without the game (read src/lib.rs top
  comment and src/families/mod.rs rules). Families read operands with `m.get`, store with `m.set`,
  read record cells with `m.read(Cell::field(table, index, "field"))` / `Cell::slot`, write with
  `m.write`, build results with `Val::derived(n, &[inputs])`, and record start values come from
  `m.initial_field_text(table, index, field)` (the field text `uw new` prints; field names are in
  `kit-meta/records/<table>.toml`).
- The kit and sample mods are git-ignored; read-only copies are inside your worktree:
  `target/ref/kit/` (= `Module_system 1.171/`). Operation meanings: `target/ref/kit/header_operations.py`
  (each op has a comment). The built atlas is `target/uw-staging/atlas.json`.
- Unit-test style to copy: `crates/uw_start/tests/flow.rs` (tiny hand-made atlas, ops by name).
- The real run (`cargo test --release -p uw_start -- --ignored --nocapture`) prints the unmodelled
  operations; do NOT run it in debug (too slow).
- Never guess an operation's effect: if the engine computes something the records do not hold
  (positions after AI movement, wages …), leave it unknown.
## Steps

Implement in `crates/uw_start/src/families/troop.rs` only. Unmodelled counts from the real run: troop_get_type 31,885; store_troop_faction 13,557 (and store_faction_of_troop); troop_set_age 4,063; store_attribute_level 1,796; store_character_level 633; store_skill_level 501; troop_equip_items 360; troop_has_item_equipped 360; store_troop_gold 110; troop_clear_inventory 110; troop_ensure_inventory_space 110; troop_add_merchandise 110; troop_set_faction; troop_set_name; troop_is_hero; troop_add_item(s); troop_remove_items; troop_raise_attribute; troop_get_upgrade_troop.
- Fields come from kit-meta/records/troops.toml (faction, flags/type, attributes, skills, level, inventory …); a `_set_` op writes `Cell::field("troops", t, "<field>")`, the matching read uses `m.read` so later reads see the write.
- Inventory changes that the engine randomises (merchandise) are written as unknown values (never invented).

## How to test

- Unit tests in crates/uw_start/tests/troop_t128.rs on a tiny atlas with a troops table (with a schema loaded from kit-meta/records/troops.toml so `initial_field_text` works): faction read/set, type from flags, attribute/skill read, set_age write. Each test asserts the op is absent from `m.report.unknown_ops`.

## Done when

- Every operation listed in Steps is modelled or explicitly left unknown with a one-line reason in the report.
- Build and tests pass.

## Do not

- Only edit src/families/troop.rs and the new test file. Do not touch src/lib.rs.

## Stop and report if

- An operation's meaning cannot be found in header_operations.py.
- A test still fails after 5 steps on it.
