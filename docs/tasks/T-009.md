# T-009: uw explain — "leads to" section

Status: ready
Budget: $0.50
Steps: 150

## Goal

`uw explain <thing>` also lists what the thing leads to (what it mentions), so both directions show.

## Known facts

- `crates/uw_cli/src/explain.rs`: `render(detail, all)` prints the used-by groups; `explain(model,
  query, all)` calls it. CLI tests in `crates/uw_cli/tests/explain.rs` run the real binary on
  `tests/fixtures/atlas_refs.json`.
- Model API (`crates/uw_cli/src/model.rs`): `model.outgoing(&Target)`, `entry_label`, `entry_hint`,
  `short`.

## Steps

1. After the used-by part, print `  leads to: N places` and groups by table (same short limits as
   used-by: 5 per group, 4 groups unless --all), rows `label  place  ops  "hint"`, only `Target::Entry`
   targets. Print nothing when there are none. Change render's parameters as needed (e.g. pass the
   model); the used-by output must stay byte-identical.

## How to test

New CLI test in tests/explain.rs: `uw explain script_game_start` on the fixture prints `leads to:` with
its menu and `script_helper`; `uw explain menu_camp` prints no `leads to` line. Existing tests pass
unchanged.

## Done when

- Tests pass; no build warnings.
