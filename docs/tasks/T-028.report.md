What changed (one file, crates/uw_decomp/src/extract/presentations.rs)
- `blocks(atlas)`: walks `atlas.tables["presentations"].entries`; for each entry takes the value as a tuple (`items` also accepts a plain array), reads field 3 (`triggers`) as a list, and for each trigger at position `i` reads `[event, ops]`, emitting `Block { table: "presentations", index: entry.index, path: [3, i, 1], label: "presentations/<name or entry.index>/<event>", ops: parse_ops(ops) }`. Reuses `crate::items` and `crate::parse_ops`; no new dependencies.
- `unreadable(atlas) -> usize`: number of trigger bodies that should be a block but `parse_ops` returns `None` (float operand, nested list, or a body that is not a list). Those emit no block.
- Both are thin wrappers over one private `walk(atlas) -> (Vec<Block>, usize)` so the table is read in one place.

Choices where the spec left room (please check if you meant otherwise)
- "`<event number>`" = the trigger's event value from field 0 (e.g. `ti_on_presentation_load` -> `-60`), not the trigger position `i`. So a label is `presentations/banner_selection/-60`.
- `Block.index` is `Entry::index` (the table index the kit uses), not the position in `entries`.
- A trigger with an empty body gives a block with `ops: []` (parse_ops succeeds); triggers whose shape is not `[integer event, body]` are skipped and not counted, since no valid block path/field exists there.
