Core bugs (report only, not fixed — shared file, other lanes edit it):
1. Unnamed tables get an empty id. py/atlas_dump.py:204/240-241 leaves `name` and `id` null for triggers/simple_triggers; `record_id` (crates/uw_decomp/src/records.rs:148-151) falls back to `""`, `print` emits `trigger  {` (records.rs:164-165), and `parse` rejects the empty id (records.rs:231-239). Actual failures: `": line 1: expected the record id"` for all 25 triggers and all 110 simple_triggers. Suggested fix for the core lane: fall back to `entry.index` for unnamed tables (or allow/quote an empty id consistently).
2. Dialog ids contain `:`. The kit's ids are `dlga_<in>:<out>[.N]` (Module_system 1.171/process_dialogs.py:145,154, dumped at py/atlas_dump.py:230). `print` writes the id unquoted (records.rs:165), while `parse` reads ids with `word()`, whose charset excludes `:` (records.rs:383-395), so it reads only `dlga_start` and then fails. Actual failures: `"dlga_start:close_window: line 1: expected `{` after `dialog dlga_start`"` for all 2773 dialogs. `parse` already accepts a quoted id (records.rs:232-234); printing ids quoted (or widening the id charset) would fix it.
3. Latent second dialog blocker: dialog entries are Python lists, dumped as `{"list": [...]}` (py/atlas_dump.py:76-77; this shape is modelled in crates/uw_decomp/src/extract/dialogs.rs:69-84). `record_values` unwraps it for printing, but `parse` always rebuilds a `Json::Array` (records.rs:298) and `roundtrip_table` compares that against the original `{"list": …}` object (records.rs:336). Once bug 2 is fixed, dialogs would still fail with "print/parse changed the record value" unless the top-level list/tuple shape is preserved or the round-trip normalises it.
