## Amaç (v1 — tek tablo kanıtı)

```
override troop swadian_recruit {
  agility 18
  name "Çırak"
}
```

- Patch kipinde derleme, o Native kaydını **değiştirilmiş hâliyle** üretir; başka hiçbir kayıt değişmez.
- Bilinmeyen alan / uymayan değer → hata + `dosya:satır` + öneri (sessiz bozulma yok).
- Değiştirilmeyen proje **bayt bayt aynı** kalır.

**v1 kapsamı: yalnız `troops` tablosu.** Kanıt sağlanınca aynı yol diğer tablolara açılır (aynı şema makinesi).

## Nasıl (uygulama notları)

1. **Kabul (`uw_check:2355`)**: `menu` dışındaki kind'ler için, hedef ad tabloda bulunuyorsa ve tablo
   şeması varsa `members`'ı `record_copy`'nin kullandığı şema denetiminden geçir. Şema yoksa eski hata
   (`E0201_NOT_YET`) kalsın — yanlış genişletme yok.
2. **Üretim (`uw_emit` / patch yolu)**: değişen kayıt, `module_<tablo>.py` sarmalayıcısında
   `from native_module_<tablo> import *` + kaydın alanlarını yazan satır olarak üretilir (bugünkü
   `uw_runtime` değişiklik kalıbıyla aynı ruh: yerinde mutasyon yok, değişen girdi kopyalanır).
   `uw_emit/src/lib.rs:153` `# {patch.origin}` yorumu korunur (modcu hangi satırın ne yaptığını görür).
3. **Etki raporu (T-117) ile birleşme**: `override troop … { faction … }` gibi bir değişiklik, T-117'nin
   zincir tablosuna yeni bir satır ekler (ör. bir askerin faction'ı değişince oyundaki etkisi).
4. **Testler**:
   - `uw_check`: `override troop x { agility 18 }` kabul; `override troop x { yok_boyle_alan 1 }` hata + öneri.
   - emit: üretilen `.py`'de ilgili kaydın alanı değişmiş; başka kayıt değişmemiş.
   - bayt eşitliği: değişmemiş proje 32/32.
5. **Doğrulama**: `cargo build --workspace`, `cargo test --workspace`, `uw build-project --compare-native`.
