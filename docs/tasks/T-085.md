# T-085: `save` — a named value that lasts (P6)

Status: ready
Budget: $1.20
Steps: 350

## Goal

Easy-language example §1 (docs/arsiv/meclis-yon1-yon2/kolay-dil-taslak.md): `save rich = false` once at the top of a file,
then `rich = true`, `when not rich`, `if rich { }` with no `$g_` prefix. It is a Native global that lives in
the save game.

## Known facts

- Globals are `$name` today (`Arg::Global`), assigned with `Stmt::Assign`; conditions in crates/uw_check.
- Game names (`praven`) and constants are resolved for bare names in check (`Arg::Name`); `save` names must
  not clash with them (error).

## Steps

1. Syntax: top-level `save <name> = <int | true | false>`. `true`/`false` are 1/0.
2. Check: a bare name that is a `save` name means global `$<name>` everywhere (operands, assignment targets,
   conditions; `not rich` = `rich == 0`, bare `rich` in a condition = `rich != 0`). Two saves with one name,
   or a save name equal to a game name / constant / op: error.
3. The start value is set once at game start: append `assign` ops to the `game_start` script
   (the same way `on game.start` is emitted).
4. Golden crates/uw_cli/tests/golden/save_values/.

## How to test

The golden fails if a save name emits as anything but `$<name>` or the start value is not assigned at game start.

## Done when

- Build and tests pass; existing goldens unchanged.

## Do not

- Touch lib/**, crates/uw_decomp/**, crates/uw_cli/src/**.

## Stop and report if

- `true`/`false` collide with existing names in the fixture or Native. 5 failed steps.
