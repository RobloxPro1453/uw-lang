# T-119: `override` and `like` for every record table, from schema data (YÖN-3 P1)

Status: ready
Budget: $4.00
Steps: 350

## Goal

A modder can change an existing record or copy one as a new record in ANY of the 27 tables
(`override faction kingdom_1 { … }`, `item my_sword like sword_medieval_a { … }`), not only troops
and parties. No table-specific Rust code: the table is found from the schema files.

## Known facts

- `copy_table(kind)` (crates/uw_check/src/lib.rs:2121) hard-codes `troop`→troops and
  `town|castle|village|party`→parties. Call sites: lib.rs:2144, :2364, :2874.
- Every schema in `kit-meta/records/*.toml` has `kind = "..."` and `table = "..."` (27 files:
  faction, item, skill, scene, quest, party_template, map_icon, …). The checker already loads
  these schemas (`Schema`, field `kind`, `table`).
- The override path (lib.rs ~2420-2485) builds `Action::ReplaceRecord` through `record_copy`
  (lib.rs:1044); the `like` path builds the new record the same way. `uw_runtime.replace_entry`
  / `find` look records up by their bare name (`swadian_recruit`, not `trp_swadian_recruit`).
- docs/tasks/T-118.report.md explains the override path end to end.

## Steps

1. Replace `copy_table` with a lookup over the loaded schemas (`schema.kind == kind` → `schema.table`),
   keeping the aliases `town|castle|village` → parties. Keep a small deny list for kinds whose
   keyword already means something else in the language (`menu`, `dialog`, `script`, `trigger`,
   `simple_trigger`, `presentation`, `mission_template`): those keep their current behaviour.
2. Make `override <kind>` and `<kind> <id> like <id>` work for every other schema kind.
3. Unnamed / duplicate-name records: keep the existing `#n` rule; unnamed tables stay an error.

## How to test

Add golden tests under crates/uw_cli/tests/golden/ (copy the layout of `troop_like` and
`town_like`): `faction_override`, `item_like`, `skill_override`. Each input.uw starts with a line
`// covers: <table>.override` or `// covers: <table>.like`. The expected module_*.py must contain the
`replace_entry` / added record for that table; the test fails if the record is not changed.
Add unit tests in uw_check for: unknown field on a faction → E0218; `override menu` still behaves as before.

## Done when

- `override` and `like` compile for faction, item, skill, scene, quest, party_template, map_icon,
  scene_prop, sound, music (track), mesh … (all non-denied kinds).
- No `match` on table names added anywhere; `copy_table` derives from schemas.
- Build and tests pass.

## Do not

- Do not touch py/uw_runtime.py, crates/uw_decomp/src/project/, crates/uw_cli/src/build_project.rs.
- Do not change the existing golden expected outputs.

## Stop and report if

- A table's records cannot be printed/read back through `record_copy` (report which tables).
- A test still fails after 5 steps on it.
