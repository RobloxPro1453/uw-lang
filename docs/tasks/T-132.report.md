Choices on the places the spec leaves open (none blocked the work, all documented in the code)
- Statements have no terminator, so `Newline` is a token; `return` takes a value only on its own line (otherwise `return`⏎`x = 5` would swallow the next statement). `ui` and `when` are words, not keywords (§2's keyword list omits `when`; `ui` is not a keyword per §2).
- `per <unit>` is part of the number token, so `2 * 5 per second` simply has no reading; a bad unit is an error.
- `150%` → 150; a fractional percent (`0.5%`) is not defined by §2 and is rounded to the nearest whole (1). Nothing in the repo relies on this yet — say so if you want a different rule.
- `File.feature` is the `feature` argument; `file` is only used in messages (the ast comment says main.uw → "main", and the caller knows the path).
- `(expr)` is transparent (the AST has no paren node); `else if` becomes a one-statement else-block, since `Stmt::If.otherwise` is a `Block`.
- The unclosed-`{` error points at the line of the brace that is never closed; the test pins that.
