What changed

1. `crates/uw_lower/src/lib.rs`
   - The `Stmt::Require | Attempt | For` arm of `Lower::stmts` now dispatches: `Require` calls the existing `self.cond` (the exact code an `if` head uses, so `and` = sequence, pure `or` = `this_or_next|` chain, `not` = flipped compare / `neg|`, composite = flag temporary). Nothing else is emitted for `require`.
   - New `Lower::attempt`: `try_begin`, arm 1, `else_try` before every later arm, `try_end` (one arm ⇒ no `else_try`).
   - New `Lower::for_stmt`: `op(var, args…)`, body via `self.stmts`, then `try_end`. Operation names are emitted as strings drawn from the node; no numeric codes anywhere.

2. `crates/uw_check/src/lib.rs`
   - The `Stmt::For` arm now calls a new `Ctx::for_stmt`. It builds the name `"try_for_" + kind`, looks it up with `Atlas::op`; when the name is missing it reports E0001 `'try_for_x' is not a Native operation` with a help line listing the `try_for_*` names read from `self.atlas.ops` (no list in code). The loop variable must be `$global`/`:local` (reuses `Ctx::local`, so `:_` is still E0210; other arg forms are rejected with E0212 and the message "the loop variable must be a $global or a :local"). Values go through `Ctx::value` like call args, and the arity rule mirrors `call`: `min_args(op)` compared against `1 + args.len()` (the loop variable counts as a value), E0203 with the Native signature as help and `header_operations.py:<line>` as note. The body is checked with `self.stmts`. A statement is only produced when the operation and the variable are valid.
