**Rules I had to pin down (spec left them open)**
- Matching: a pattern's last part is the property/field name and the pattern's earlier parts must end the object path (`player.agent.speed` matches `agent.speed`); the object is the path minus the name and is only lowered when a template uses `{object}`, so `player.name` never has to resolve the word `player`. Fields follow the same rule, so a field write needs its object in front (`player.agent.stamina`); a bare `agent.stamina` is an "unknown name" error rather than a guess.
- `in lo..hi` is inclusive of `hi`, while `val_clamp`'s upper bound is exclusive, so it is emitted as `hi + 1` (e.g. `0..100` → `val_clamp …, 0, 100001`). That also means the v0 fixture `var agent.stamina = 100 in 0..100` clamps to 100, not 99.
- `var agent.stamina` gets a slot one above the highest `slot_agent_*` constant of the atlas, allocated per (kind, name).
