# T-170: easy names for unnamed kit operations, part 4 of 4 (ROADMAP D0)

Status: ready
Budget: $0.30
Steps: 150

## Goal

Give an easy English name to 31 kit operations that no automatic rule could name, so the UW
vocabulary has no empty entry. Output is one new data file; nothing else changes.

## Known facts

- Each operation's entry (kind, kit line, comment) is in `kit-meta/easy/manual.toml` (search `native = "<name>"`).
- The naming rules are `docs/meclis/yon3/dil/D3-SOZLUK.md` §2 (read the rule table and the examples).
  Already-named operations and their style are in `kit-meta/easy/ops.json` (`"easy"` / `"native"` pairs):
  e.g. `agent.horse`, `agent.play_sound`, `party.is_active`, `call.script`, `math.*`.
- Your operations: `talk_info_set_line`, `change_screen_return`, `change_screen_loot`, `change_screen_trade`, `change_screen_exchange_members`, `change_screen_trade_prisoners`, `change_screen_buy_mercenaries`, `change_screen_view_character`, `change_screen_training`, `change_screen_mission`, `change_screen_map_conversation`, `change_screen_equip_other`, `change_screen_map`, `change_screen_notes`, `change_screen_quit`, `change_screen_give_members`, `change_screen_controls`, `change_screen_options`, `disable_menu_option`, `convert_to_fixed_point`, `convert_from_fixed_point`, `shuffle_range`, `store_item_value`, `store01_random_parties_in_range`, `reset_mission_timer_a`, `reset_mission_timer_b`, `reset_mission_timer_c`, `show_troop_details`, `rebuild_shadow_map`, `this_or_next`, `neg`.

## Steps

1. For each operation read its `manual.toml` entry (`doc`, `kind`, `note`). If `note` says "name clash",
   the obvious name is already taken: pick a different, still natural one.
2. Choose the name the rules would give (subject.verb / subject.property, lower snake case with dots). Prefer
   the word already used for the same concept in `ops.json` (search it). Do not reuse an easy name that
   `ops.json` already has for the same `kind`.
3. Write `kit-meta/easy/manual-names/part-4.toml`: one block per operation, in the order above:
   `[[name]]` / `native = "<kit name>"` / `easy = "<easy name>"` / `why = "<rule id or one short reason>"`.

## How to test

`cargo build --workspace` must pass. Check by search that every `native` you wrote appears in
`kit-meta/easy/manual.toml` exactly as written, that the file has exactly 31 blocks and that no two
`easy` values in your file are equal.

## Done when

- `kit-meta/easy/manual-names/part-4.toml` exists with 31 blocks, one per listed operation.

## Do not

- Do not edit `manual.toml`, `ops.json`, any code, or any other part file.
- Never change or invent a `native` name; copy it exactly.

## Stop and report if

- An operation from the list is not in `manual.toml`.
- A test still fails after 5 steps on it.
