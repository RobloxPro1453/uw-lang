# T-126: uw_start runs game_start in seconds (performance)

Status: ready
Budget: $4.00
Steps: 300

## Goal

The real `game_start` dry run takes ~5 minutes in release (18.7M operations). Make it run in under 15 s in release with exactly the same result, so the compiler can run it on every build.

## Known facts

- Crate `crates/uw_start` runs Native's `script_game_start` without the game (read src/lib.rs top
  comment and src/families/mod.rs rules). Families read operands with `m.get`, store with `m.set`,
  read record cells with `m.read(Cell::field(table, index, "field"))` / `Cell::slot`, write with
  `m.write`, build results with `Val::derived(n, &[inputs])`, and record start values come from
  `m.initial_field_text(table, index, field)` (the field text `uw new` prints; field names are in
  `kit-meta/records/<table>.toml`).
- The kit and sample mods are git-ignored; read-only copies are inside your worktree:
  `target/ref/kit/` (= `Module_system 1.171/`). Operation meanings: `target/ref/kit/header_operations.py`
  (each op has a comment). The built atlas is `target/uw-staging/atlas.json`.
- Unit-test style to copy: `crates/uw_start/tests/flow.rs` (tiny hand-made atlas, ops by name).
- The real run (`cargo test --release -p uw_start -- --ignored --nocapture`) prints the unmodelled
  operations; do NOT run it in debug (too slow).
- Never guess an operation's effect: if the engine computes something the records do not hold
  (positions after AI movement, wages …), leave it unknown.
## Steps

1. Measure first (release): where the time goes. Likely: `op_name` decodes each op every time (atlas lookup + string match), locals are `HashMap<String,_>`, `Val::derived` clones dependency sets (`BTreeSet<Cell>`) on every arithmetic step.
2. Decode each script once into a compact form (op name as an enum or interned id, flags, operands pre-resolved: local slot index / global / register / constant). Keep the `Node` tree idea.
3. Dependencies: share `Rc` sets instead of copying when only one input has deps; cap a set at 256 cells (then mark the value `wide` and keep the cap) — document it.
4. Keep the PUBLIC API used by families unchanged: `Machine::get/set/read/write/random/unknown_op/initial_field_text/entry/resolve`, `Val::derived/num/unknown`, `Cell::slot/field`, `families::exec(m, name, args)` with `args: &[Json]`. Other tasks write families in parallel against this API.

## How to test

- Keep tests/flow.rs green unchanged.
- In tests/native_game_start.rs: remove the `#[ignore]`, run game_start twice and assert identical `cells`; print the time. Add an assertion that the run takes < 60 s even in debug (if debug cannot reach it, keep the test ignored and say why in the report, with release numbers).
- Before/after: the snapshot (`cells` map) must be identical to the slow version: save the slow version's cell count and a hash of the cells in the report and compare.

## Done when

- Every operation listed in Steps is modelled or explicitly left unknown with a one-line reason in the report.
- Build and tests pass.

## Do not

- Do not edit src/families/party.rs, troop.rs, faction.rs (other tasks). Do not change semantics.

## Stop and report if

- An operation's meaning cannot be found in header_operations.py.
- A test still fails after 5 steps on it.
