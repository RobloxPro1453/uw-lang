# T-014: Parser — assignments, expressions, if / else if / else, conditions

Status: ready
Budget: $1.50
Steps: 250

## Goal

`uw_syntax::parse` reads the statement forms of grammar 2 into the AST types that already exist in
`crates/uw_syntax/src/lib.rs` (`Stmt::Assign`, `Stmt::If`, `Expr`, `Cond`, `AssignOp`, `BinOp`, `CmpOp`).

## Known facts

- Binding spec: `docs/arsiv/meclis-yon1-yon2/gramer-2-oneri.md` sections 1, 2, 7 (precedence `not` > `and` > `or`;
  arithmetic like Python; `==` `!=` `>` `>=` `<` `<=`; `= += -= *= /= %=`; a line continues inside
  parens or when it ends with a binary operator / `and` / `or` / `not` / `=`; `else if` ok; `elif` and
  `else:` are errors with a one-line fix hint, like the existing `if`-rejection code in `fn stmt`).
- Statement start: `$g` / `:l` / register name followed by an assign op -> `Stmt::Assign`; `if` ->
  `Stmt::If`; otherwise the existing call parsing -> `Stmt::Call`. `and` `or` `not` `if` `else` are keywords.
- A condition operand that is a call (`party_is_active(p_town_6)`) is `Cond::Call`; a comparison is
  `Cond::Cmp`. A `-5` literal stays `Expr::Value(Arg::Int(-5))`.
- Error messages English, never only "unexpected end of file" (KARARNAMELER, Sözdizimi).

## Steps

   `and`, the `elif` error.
