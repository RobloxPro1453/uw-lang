# T-169: easy names for unnamed kit operations, part 3 of 4 (ROADMAP D0)

Status: ready
Budget: $0.30
Steps: 150

## Goal

Give an easy English name to 32 kit operations that no automatic rule could name, so the UW
vocabulary has no empty entry. Output is one new data file; nothing else changes.

## Known facts

- Each operation's entry (kind, kit line, comment) is in `kit-meta/easy/manual.toml` (search `native = "<name>"`).
- The naming rules are `docs/meclis/yon3/dil/D3-SOZLUK.md` §2 (read the rule table and the examples).
  Already-named operations and their style are in `kit-meta/easy/ops.json` (`"easy"` / `"native"` pairs):
  e.g. `agent.horse`, `agent.play_sound`, `party.is_active`, `call.script`, `math.*`.
- Your operations: `leave_encounter`, `encounter_attack`, `select_enemy`, `auto_set_meta_mission_at_end_commited`, `end_current_battle`, `reset_item_probabilities`, `inflict_casualties_to_party_group`, `distribute_party_among_party_group`, `close_order_menu`, `get_scene_boundaries`, `add_missile`, `scene_item_get_num_instances`, `scene_item_get_instance`, `scene_spawned_item_get_num_instances`, `scene_spawned_item_get_instance`, `class_set_name`, `replace_scene_props`, `replace_scene_items_with_scene_props`, `cast_ray`, `finish_mission`, `start_mission_conversation`, `add_reinforcements_to_entry`, `add_point_light`, `add_point_light_to_entity`, `particle_system_add_new`, `particle_system_emit`, `particle_system_burst`, `particle_system_burst_no_sync`, `spawn_item_without_refill`, `mission_cam_get_aperture`, `talk_info_show`, `talk_info_set_relation_bar`.

## Steps

1. For each operation read its `manual.toml` entry (`doc`, `kind`, `note`). If `note` says "name clash",
   the obvious name is already taken: pick a different, still natural one.
2. Choose the name the rules would give (subject.verb / subject.property, lower snake case with dots). Prefer
   the word already used for the same concept in `ops.json` (search it). Do not reuse an easy name that
   `ops.json` already has for the same `kind`.
3. Write `kit-meta/easy/manual-names/part-3.toml`: one block per operation, in the order above:
   `[[name]]` / `native = "<kit name>"` / `easy = "<easy name>"` / `why = "<rule id or one short reason>"`.

## How to test

`cargo build --workspace` must pass. Check by search that every `native` you wrote appears in
`kit-meta/easy/manual.toml` exactly as written, that the file has exactly 32 blocks and that no two
`easy` values in your file are equal.

## Done when

- `kit-meta/easy/manual-names/part-3.toml` exists with 32 blocks, one per listed operation.

## Do not

- Do not edit `manual.toml`, `ops.json`, any code, or any other part file.
- Never change or invent a `native` name; copy it exactly.

## Stop and report if

- An operation from the list is not in `manual.toml`.
- A test still fails after 5 steps on it.
