# T-080: Party records read like the game: icon, no menu, no target (P5)

Status: ready
Budget: $1.20
Steps: 300

## Goal

The owner opened `parties/towns/town_6.uw` (Praven) and saw `rest 12`, `menu 0`, `ai_target 0`. They should
read `icon town` (inside party_flags), `menu none`, `ai_target none`; same in party_templates and any other
table where a `0` means "nothing" by the kit's own name (`no_menu`, ...).

## Known facts

- Kit: `("town_6","Praven", icon_town|pf_town, no_menu, pt_none, fac_neutral,0,ai_bhvr_hold,0,(-96, 26.4),[], 155)`
  (Module_system 1.171/module_parties.py:82, read-only). Map icon 12 = `icon_town` (atlas map_icons index 12).
- Types: crates/uw_decomp/src/records.rs (`ref:<table>`, `flags`, `bits` with `parts`, `list`); schemas
  kit-meta/records/*.toml. A plain `ref:menus` would print 0 as the first menu — wrong: 0 here means none.
- Measure: `uw roundtrip` records block stays exact 12815/12815; `uw new` + `uw new --check` exact.

## Steps

1. records.rs: a ref may declare its "nothing" value (e.g. `none = 0` in the field TOML): that value prints
   `none` and `none` reads back as it. A bits part may be `ref:<table>` (the icon part prints `icon_town`
   or, with game names installed, whatever `Atlas::game_name` gives; else the kit id).
2. parties.toml / party_templates.toml: icon as its own part of party_flags (mask from the kit:
   header_parties.py), `menu` as ref:menus with none 0, `ai_target` as ref:parties with none 0 if the kit
   says it is a party (else leave raw and say why). Cite kit lines in `source`.
3. Any other schema field the kit documents the same way: list them in the report, change only the clear ones.

an icon part reading `icon_town`, no `rest 12`; every parties/party_templates record reads back exact.
