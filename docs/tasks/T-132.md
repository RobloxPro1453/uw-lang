# T-132: parser for the UW core language v0

Status: ready
Budget: $3.00
Steps: 300

## Goal

`crates/uw_core` can read core-language files (main.uw, features/*.uw) into the syntax tree, with clear
`file:line` errors.

## Known facts

- Spec: docs/dil/CORE-v0.md §2-§3 (lexical rules, grammar, keyword list). The syntax tree is fixed in
  crates/uw_core/src/ast.rs (do not change it; if you think it must change, stop and report why).
- Example input: crates/uw_core/tests/alex/ (main.uw, features/stamina.uw, features/sprint.uw).
- Numbers are thousandths (`0.5` → 500, `12` → 12000); percent keeps the number (`150%` → 150);
  `15 per second` → Rate { milli: 15000, unit: Second }; colors `#3FA34D` → 0x3FA34D; strings with `{expr}`
  become TextPart pieces.

## Steps

1. Add `src/lex.rs` (tokens with spans/lines) and `src/parse.rs` with
   `pub fn parse(feature: &str, file: &str, text: &str) -> Result<ast::File, Vec<Error>>`; export in lib.rs.
2. Precedence per spec §3; `while in <path>` vs `while <expr>`; `otherwise` only after a `while` block.
3. Error recovery: report several errors per file when possible (skip to next item).

## How to test

crates/uw_core/tests/parse.rs: parse each Alex file and assert the exact shape of key items (the `var
agent.stamina` has kind agent, range 0..100 as Number{0}/Number{100000}; sprint's While has cond Binary And
with Call key.held(alt), and an otherwise block; stamina's ui item has 6 props, color 0x3FA34D, size Tuple
of two numbers). Plus error tests: missing `}` → error with the right line; `otherwise` without while →
error; unknown character → error.

## Done when

- All three Alex files parse; error tests pass; build and tests pass.

## Do not

- Do not edit src/ast.rs or any other crate.

## Stop and report if

- The grammar is ambiguous somewhere (report the exact case).
- A test still fails after 5 steps on it.
