# T-030: Record format core: lossless print/parse of Native records (P1)

Status: ready
Budget: $2.00
Steps: 400

## Goal

`uw_decomp::records` turns every atlas record (troop, item, party …) into UW record text
`<kind> <id> { <field> <value> … }` and parses it back to the identical atlas value. Decision:
docs/arsiv/meclis-yon1-yon2/YON2-KARAR.md §2 (read §2 only). Round 1 is RAW: values exactly as in the atlas, no flag or
bit decoding.

## Known facts

- Atlas: `target/uw-staging/atlas.json` (not in git, 6.5 MB). `atlas.tables[<t>].entries[i]` =
  `{index, id, name, value}`; `value` is the kit tuple as JSON: a JSON array = Python tuple,
  `{"list": [...]}` = Python list. Example parties entry: `["zendar","Zendar",2114828,0,0,3,0,0,0,[18,60],{"list":[]}]`.
  Troop values hold integers up to ~2^230 (face codes, packed attributes).
- `uw_atlas` reads JSON with plain `serde_json` (crates/uw_atlas/Cargo.toml:10): numbers above u64 become
  f64 and LOSE digits. Fix: enable serde_json feature `arbitrary_precision` (in uw_atlas, so the whole
  workspace unifies on it), then keep big integers as decimal strings in `Value::Int`.
- Existing helpers: crates/uw_decomp/src/lib.rs (`items` unwraps `{"list": …}`), roundtrip.rs (report style).

## Steps

1. Enable `arbitrary_precision`; run `cargo test --workspace` and `target/debug/uw roundtrip` (or the
   cargo-run equivalent): it must still say 9113 blocks, 0 failed. If not, stop (see below).
2. New module crates/uw_decomp/src/records.rs:
   - `enum Value { Int(String) /* decimal, may be negative */, Float(String), Str(String), Ident(String),
     List(Vec<Value>), Tuple(Vec<Value>) }`; `fn from_json(&Json) -> Value`, `fn to_json(&Value) -> Json`
     (inverse; `to_json(from_json(v)) == v` for every atlas value).
   - Schema: `struct Schema { table, kind, id_prefix, fields: Vec<Field{name, ty, optional, source}> }`
     loaded from `kit-meta/records/<table>.toml` (add `toml` + `serde` deps). In round 1 `ty` may be only
     `"raw"`. A record with more values than fields prints the extras as `field_<n>`; fewer values than
     fields is allowed only for `optional = true` trailing fields.
   - `fn print(schema, entry) -> String`: `kind id {` then one `name value` line per field, `}`. Id = entry
     id without the table prefix (`trp_knight_1_1` → `knight_1_1`). Strings escaped (`\"`, `\`, `\n`).
     Lists `[a, b]`, tuples `(a, b)`, one-element tuple `(a,)`.
   - `fn parse(schema, text) -> Result<(String /*id*/, Json), String>`: errors name the line.
   - `fn roundtrip_table(atlas, schema) -> TableReport { records, exact, failed, first_failures }`.
3. Pilot schema `kit-meta/records/factions.toml`: field names from the header comment of
   `Module_system 1.171/module_factions.py` (snake_case English, each field `source = "module_factions.py:<line>"`);
   a value with no kit comment is `field_<n>`. No invented names.
4. Tests: inline tiny atlas (shape like crates/uw_cli/tests/fixtures/atlas_golden.json) with a tuple, a list,
   a negative int, a 2^200 int, a float, a string with quote; plus a real-atlas test (skip if file missing)
   asserting factions: 34 records, 34 exact.

## How to test

Round-trip test compares `to_json(parse(print(x)))` with the atlas JSON; fails if any digit, list/tuple
kind or string escape is lost.

## Done when

- factions 34/34 exact on the real atlas; all workspace tests green; `uw roundtrip` still 9113/0.

## Do not

- Touch crates other than uw_decomp and the one Cargo feature line in uw_atlas; no kit writes; no flag or
  bit decoding (round 2).

## Stop and report if

- `arbitrary_precision` changes the ops round-trip result or breaks a test you cannot fix in 5 steps.
- The atlas value shape differs from the facts above.
