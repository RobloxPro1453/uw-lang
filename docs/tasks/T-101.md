# T-101: VS Code shows UW errors as you save

Status: ready
Budget: $0.80
Steps: 200

## Goal

In VS Code, saving a .uw file runs `uw check --json <folder>` and shows each error as a red squiggle and in
the Problems panel; fixing it and saving clears it.

## Known facts

- Extension folder: editors/vscode/ (T-098: package.json, grammar, README). No npm dependencies may be
  required to run it (plain JavaScript `extension.js`, the `vscode` API only).
- `uw check --json` (T-100, may land at the same time): one JSON object per line
  `{"file","line","column","end_line","end_column","severity","code","message","help"}` (1-based line and
  column), last line `{"summary":{...}}`.
- `uw` is on PATH (cargo install); the folder is the workspace folder holding the file (the nearest
  ancestor with uw.toml, else the file's folder).

## Steps

1. package.json: `main: ./extension.js`, activation on `onLanguage:uw`, a setting `uw.path` (default `uw`).
2. extension.js: on save (and on open), run the command, parse lines, set a DiagnosticCollection
   (help appended to the message); a missing `uw` shows one warning, not a crash.
3. Pure function `parseCheckOutput(text)` exported and tested by editors/vscode/test/parse.test.js runnable
   with plain `node` (no framework); plus extend crates/uw_cli/tests/vscode_grammar.rs to assert
   package.json has `main` and the activation event.

## How to test

`node editors/vscode/test/parse.test.js` exits non-zero if a sample line maps to the wrong range.

## Done when

- README (Turkish) says how to see errors. Build and tests pass.

## Do not

- Touch anything outside editors/vscode/ and crates/uw_cli/tests/vscode_grammar.rs.

## Stop and report if

- The extension cannot run without npm packages.
