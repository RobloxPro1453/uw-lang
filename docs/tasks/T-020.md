# T-020: Decompiler: Native operation block -> UW text

Status: ready
Budget: $2.00
Steps: 400

## Goal

`uw_decomp::decompile::decompile(atlas, ops, mode)` prints a Native operation block as UW statements
that, parsed and checked back, give exactly the same operations (round-trip). Part of the kaldıraç plan
(docs/meclis/DEVIR.md, section 00000).

## Known facts

- Skeleton is in place: crates/uw_decomp/src/lib.rs (`RawOp {code, args}`, `RawArg::{Int,Str}`,
  `to_raw`), crates/uw_decomp/src/decompile.rs (stub + `Mode`). Fill ONLY decompile.rs.
- Op names: `atlas.op_for_code(code)` clears flag bits. Flags: neg = 2147483648, this_or_next =
  1073741824 (`atlas.op("neg")`, `atlas.op("this_or_next")`). Real codes: try_end 3, try_begin 4,
  else_try 5, try_for_range 6, ge 30, eq 31, gt 32, party_is_active 132, assign 2133. `lt`, `neq`,
  `le` are NOT atlas ops: they are `neg|ge`, `neg|eq`, `neg|gt`.
- UW syntax today: crates/uw_syntax/src/lib.rs and docs/kilavuz/UW_KILAVUZU.md §3. How the checker
  lowers `if`/`and`/`or`/`not`/comparisons back to ops: crates/uw_check/src/lib.rs `cond_ops_into`,
  `not_ops_into`, `or_ops_into` (an `or` of single ops -> `this_or_next|` on all but the last).
- Task T-021 (parallel) adds flagged call names `neg|eq(a, b)` and `this_or_next|x(...)` to the parser.

## Steps

1. Raw mode: one line per op `name(args)`; flags as `neg|name` / `this_or_next|name` /
   `neg|this_or_next|name`; no-operand ops as `name()`. Args: Int -> number (negatives too); Str
   starting `$` or `:` -> as is; Str that is an identifier `[A-Za-z_][A-Za-z0-9_]*` AND
   `atlas.resolve_ref(s).is_some()` -> bare name; any other Str -> quoted text, escaping `\` `"` and
   newline as `\` `\"` `\n`. Indent by 4 spaces inside try_begin/try_for_*..try_end (cosmetic only).
   Unknown code -> a line `// unknown operation <code>`.
2. Structured mode: `assign(x, v)` with x `$`/`:` -> `x = v`. A try_begin..try_end is "clean" when
   every arm starts with one or more condition ops (`can_fail`, comparisons, or flagged) and only the
   last arm may have none (-> `else`). Clean -> `if c { … } else if c { … } else { … }`, bodies
   recursively. Conditions: eq/gt/ge -> `a == b`/`a > b`/`a >= b`, neg|eq/neg|gt/neg|ge ->
   `!=`/`<=`/`<`, other neg|op -> `not op(...)`, a run of this_or_next ops ending in one plain op ->
   `a or b or c`, the parts joined by `and`. Anything not clean stays raw for that try block.
3. Unit tests in decompile.rs with a tiny inline atlas (`Atlas::from_str`; shape: the
   `atlas()` helper in crates/uw_check/src/lib.rs tests, or crates/uw_cli/tests/fixtures/atlas_golden.json).

## How to test

`decompile_raw_*` and `decompile_structured_*` tests: build `Vec<RawOp>` by hand, assert the exact
output string. Cover: flags, negative int, quoted text with a quote inside, bare ref vs unknown string,
if/else if/else, or-chain, `not`, non-clean try kept raw, nested try.
