# T-087: One place opens `fn` words (remove the copy in roundtrip.rs)

Status: ready
Budget: $1.20
Steps: 300

## Goal

`fn` and object words are opened by uw_check only. Today project blocks use a copy in
crates/uw_cli/src/roundtrip.rs `compile_with` (T-084); mod folders use uw_check's own (T-078/T-082).
The copy can drift (docs/CHECKUP.md "fn açma iki yerde").

## Known facts

- uw_check: `check(atlas, sources, fallback)` collects fns from sources; `check_block(atlas, file, stmts)`
  (crates/uw_check/src/lib.rs ~1344) checks one block with an empty fn map.
- `compile` (no fns) must stay byte-for-byte the same path: `uw roundtrip` measures depend on it.

## Steps

1. uw_check: `pub fn check_block_with(atlas, file, stmts, sources: &[Source])` that collects fns from
   `sources` (same rules and errors as `check`, incl. duplicate names between sources = error) and opens
   calls/object words exactly as `check` does; `check_block` = `check_block_with(.., &[])`.
2. roundtrip.rs `compile_with`: call it; delete the copied expansion code.
3. Keep every existing test; add one in uw_check: an object word read inside an `if` condition in a block
   given lib sources (the case the copy did not handle).

## How to test

Existing build_project word test and goldens unchanged; the new uw_check test fails without step 1.

## Done when

- crates/uw_cli/src/roundtrip.rs has no fn expansion of its own. Build and tests pass.

## Do not

- Touch crates/uw_syntax, crates/uw_decomp, lib/**, kit-meta/**.

## Stop and report if

- `check_block_with` would change any output of `compile` with no fns. 5 failed steps.
