# T-075: Record field and part names are full English words (P5b)

Status: ready
Budget: $1.00
Steps: 250

## Goal

The modder reads `strength 20, agility 20, intelligence 15, charisma 25` in a troop, not `str/agi/int/cha`;
the same for every other abbreviated field or part name in the record schemas.

## Known facts

- Schemas: kit-meta/records/*.toml; `name = "str"` at troops.toml:79, `name = "agi"` at :85 (attributes parts).
- Printing/parsing is schema-driven (crates/uw_decomp/src/records.rs): renaming in TOML changes both sides.
- Measure: `cargo run -p uw_cli -- roundtrip` records block must stay exact (12815/12815).

## Steps

1. In every kit-meta/records/*.toml, expand each abbreviated field/part/enum name to the full English word
   (str->strength, agi->agility, int->intelligence, cha->charisma, and any similar: `prof`, `num`, `pos`,
   `dir`, `spd`, `dmg`...). Keep the kit wording when the kit spells it out (comment the kit line in `source`).
   Names already full words stay. Do not rename Native constant names (`tf_hero`, `pf_...`): only UW's own names.
2. Update tests under crates/*/tests that assert the old names in printed text.
3. Add crates/uw_decomp/tests/names_t075.rs (skip if the atlas is missing): print trp_knight_1_1 and assert
   `strength 20` and `agility 20` appear and `str 20` does not; plus a scan over all schema TOML files
   asserting no field/part name is in the list of old abbreviations you replaced.

## How to test

names_t075 fails if any old short name comes back; the roundtrip tests fail if renaming broke reading back.

## Done when

- No abbreviated UW-own name left in the schemas; list every rename in the report (old -> new).
- Build and tests pass; records still 12815/12815 exact.

## Do not

- Touch crates/uw_decomp/src/** or any crate source: only kit-meta/records/*.toml and tests.

## Stop and report if

- A rename makes two fields of one table share a name. A test still fails after 5 steps on it.
