# T-112: Apply the smart-audit findings (records read clearly), round 1

Status: ready
Budget: $2.00
Steps: 500

## Goal

The audit reports list fields a modder misreads. Fix the ones marked sure ("Kesin") so that a `uw new`
project reads clearly, e.g.

```
stacks [(farmer, 10, 20), (peasant_woman, 0, 4)]      // was [(25, 10, 20), (133, 0, 4)]
```

while an unchanged project still reads back exactly and builds byte-identical to Native.

## Known facts

- Reports: docs/bilgi/denetim/birlik-esya-krallik.md and docs/bilgi/denetim/yerler-sahneler.md (tables with
  evidence and a confidence column). Take only rows with confidence "Kesin" whose fix is a name instead of a
  number, a named flag, or a short comment. Skip anything that needs a new language construct.
- How records print/read: crates/uw_decomp/src/records.rs (schema-driven, `ref` fields resolve ids to names —
  T-080 did this for parties), schemas kit-meta/records/<table>.toml. Game names come from the names layer.
  Never invent a Native name: resolve through the atlas; an index with no entry stays a number.
- Measures (must stay as they are): `cargo test --workspace` green; real-atlas read-back tests
  (records_t0xx / readable_t0xx) exact; `uw new <dir> --check` and `uw build-project <dir> --compare-native`
  (32/32 equal) — run them if your copy has target/uw-staging/atlas.json and the kit; say so if not.

## Steps

1. Make a list (in the report) of the rows you take and the rows you skip, with the reason.
2. Implement, smallest change per row; extend readable tests (new file crates/uw_decomp/tests/readable_t112.rs)
   so each fixed row is asserted on the tiny atlas and, when present, the real atlas.

## Done when
