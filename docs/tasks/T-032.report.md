The core bug (do not fix here — other lanes share the file)

The top-level `Value::List` vs `Value::Tuple` distinction is therefore lost, and `roundtrip_table`'s `value == entry.value` (records.rs:336) can never hold when the atlas value is a Python list. The parse of all 620 item texts *succeeds* — so the field names/arity are fine; only the container shape differs. A fix has to live in the core (e.g. carry the record's container shape through print/parse, or let the schema say the record is a list); it is outside my allowed files.
