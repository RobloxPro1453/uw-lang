# T-077: Game names in `uw build` mods, and measured on every Native block (P5b)

Status: ready
Budget: $1.20
Steps: 300

## Goal

A mod written for `uw build` (examples/menu_demo) can say `praven`, `swadia`, `king_harlaus` instead of
`p_town_6`, `fac_kingdom_1`, `trp_kingdom_1_lord`; and `uw roundtrip --names` proves every Native operation
block still comes back identical when printed with game names.

## Known facts

- crates/uw_decomp/src/names.rs: `derive(atlas)`, `parse(atlas, text)`, `pairs`, `FILE` = "names.uw".
  `Atlas::set_game_names` makes resolve_ref accept game names; check emits the kit reference
  (crates/uw_check/src/lib.rs `Arg::Name`); decompile prints game names.
- crates/uw_cli/src/new.rs `install_names(atlas, dir)` reads a folder's names.uw (none → 0 names).
- `uw build` builds a mod folder in crates/uw_cli/src/build.rs; `uw roundtrip` in crates/uw_cli/src/roundtrip.rs.

## Steps

1. `uw build`: before checking, install the mod folder's names.uw if it has one, else `names::derive` (Native's).
2. `uw roundtrip --names`: install `names::derive` before decompiling; report line unchanged in form.
3. In the "unknown name" error of check (crates/uw_check/src/lib.rs, the candidate list after `Arg::Name`),
   also offer game names as suggestions.
4. Golden test crates/uw_cli/tests/golden/game_names/ (like golden/and_or_not, fixture atlas_golden.json;
   add records to the fixture only if needed): input.uw uses a game name; expected .py has the kit reference.

## How to test

The golden test fails if the game name is not accepted or is emitted as-is into Python. Add a unit test in
roundtrip.rs or tests/roundtrip.rs that runs the --names path on the fixture atlas and asserts 0 failures.

## Done when

- `cargo run -p uw_cli -- roundtrip --names` on the real atlas: identical count = total (put the line in the report).
- Build and tests pass.

## Do not

- Touch crates/uw_decomp/src/records.rs, crates/uw_syntax, crates/uw_lower, kit-meta/.

## Stop and report if

- Derived names clash with a name a test mod already uses as a local/global. A test still fails after 5 steps.
