# T-084: `uw create` projects can use UW's words too (`uw build-project` loads lib/)

Status: ready
Budget: $1.20
Steps: 300

## Goal

In a folder made by `uw create`, the modder can write `give_gold(1000)` or `player.gold += 100` inside a
record's `ops { }` block and also add their own `fn`s in any project .uw file; `uw build` builds it.

## Known facts

- `uw build` (mod folders) loads lib/*.uw first: crates/uw_cli/src/build.rs (`lib_files`, `find_lib`,
  `parse_sources`, T-079). Project builds: crates/uw_cli/src/build_project.rs; every `ops { }` block text is
  compiled by `crate::roundtrip::compile(&atlas, text)` (crates/uw_cli/src/roundtrip.rs).
- `fn` items are collected by `uw_check::check` from all sources it gets (T-078); `compile` today checks one
  block alone, so fns must be handed to it.
- Project record files hold records only; a file of only `fn` items must not be read as records
  (crates/uw_decomp/src/project/load.rs `collect_uw_files`).

## Steps

1. Give the block compile the fns of lib/*.uw plus a project's `fns/*.uw` (new folder; a file there holds
   only `fn` items). Keep compile identical when there are none (roundtrip measures depend on it).
2. load.rs: skip `fns/` like `names.uw`.
3. Test: a temp copy of a tiny project (or the fixture flow the existing build_project tests use) where one
   menu block calls `give_gold(5)`; the built module text holds `troop_add_gold`.

## How to test

The new test fails if the word is not inlined; existing roundtrip/build-project tests stay unchanged.

## Done when

- `uw new` + `uw new --check` still exact; build and tests pass.

## Do not

- Touch crates/uw_syntax, crates/uw_check, lib/**, kit-meta/**.

## Stop and report if

- Compile cannot take extra sources without changing uw_check's API (describe the change needed). 5 failed steps.
