# T-049: Re-measure the order ties: ranges and id offset arithmetic (P3b input)

Status: ready
Budget: $0.80
Steps: 250

## Goal

Our own reproducible count of what P3b must keep fixed: range constants (`*_begin/*_end`) and their chains,
and every place Native code does arithmetic with a record id or range constant (`store_add`, `store_sub`,
`val_add`, `val_sub` …). Replaces the unchecked Gemini numbers (256 ranges, 416 offset sites).

## Known facts

- Atlas: target/uw-staging/atlas.json (`ranges`, `constants`, `tables`, `ops`).
- Kit (read-only): `Module_system 1.171/`. Never run kit Python; Python 3 for your own script is fine.

## Steps

1. Write `py/order_ties.py` (read-only; prints a summary, writes target/uw-native/order_ties.json): ranges
   per table (begin/end resolved to table indices, chains `X_end == Y_begin`); offset arithmetic sites
   (table, record, op, which id or range constant), grouped by table and by constant.
2. Write the findings as `docs/bilgi/sira-baglari.md` (Turkish, at most 80 lines, [KİT] tags with
   file:line, numbers only from the script's output).

## How to test

Run the script; its summary is the report. Spot-check 3 sites against the kit by line.

## Done when

- The script runs clean; the doc has the measured numbers and 3 checked examples.

## Stop and report if
