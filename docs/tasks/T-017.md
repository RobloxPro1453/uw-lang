Status: ready
Budget: $2.00

## Goal

`uw_check::check` accepts the grammar-2 AST (already defined in uw_syntax) and produces patches:
assignments and `if` become `uw_lower::Stmt` trees (lowered by `ops()`), menu members and
`new menu_x` become the new `Action` variants (`ReplaceText`, `InsertOption`, `ChangeOption`,
`RemoveOption`, `NewMenu`) in crates/uw_check/src/lib.rs. Today these spots report E0201 "parsed but
not checked yet": replace them.

## Known facts

- Spec: `docs/arsiv/meclis-yon1-yon2/gramer-2-oneri.md` sections 3, 4, 5, 7. Strict: a new option whose id already
  exists in the Native menu -> error suggesting `change option`; `change/remove option X` missing ->
  error + suggestion; `mno_` typed -> error; ids ASCII; `new menu_x` already existing -> error; double
  prefix `menu_menu_x` -> error; a user local starting with `:_` -> error; two `text` or two
  `on enter` for one menu -> error showing both places.
- `override menu_x` has `kind == None`: the kind comes from the id prefix (atlas tables' `id_prefix`,
  `menu_` for menus); the old `override menu x` keeps working. Menu layout module_game_menus.py:20-32:
  field 2 text, 4 enter block, 5 options; an option is (id, condition, text, consequence).
- Existing helpers: `fn call` (one operation), the `Arg` -> `Value` code inside it (factor it out and
  reuse it for expression leaves), `find_menu`, `diag`, error codes at the top (add new E02xx there).
- Assignment target: `Arg::Global` / `Arg::Local` -> `Value::Ref`, a register constant ->
  `Value::Const`; anything else is an error.
- The parser for these forms lands in parallel (T-014, T-015): build the AST by hand in tests.
