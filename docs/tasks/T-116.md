## What went wrong (verified, owner's game test 2026-11-16)

T-103 rewrote `give_center_to_faction_aux p_town_6 fac_kingdom_2`, but Native game_start then runs
`(call_script, "script_give_center_to_lord", "p_town_6", "trp_kingdom_1_lord", 0)`
(Module_system 1.171/module_scripts.py:567-596), which hands Praven to King Harlaus and so back to Swadia.
Right after, line 598 runs `script_assign_lords_to_empty_centers`, which gives every center without a lord to
a lord of its own faction.

## Goal

```
party praven {
  owner vaegirs   // who gets it at game start; change it here
  lord auto       // the lord who holds it at game start: a lord's game name, or auto = the game picks one of the owner's lords
  ...
```

- `uw new` writes `lord <game name>` for every center that has an explicit give_center_to_lord line
  (`lord king_harlaus` for Praven), and `lord auto` for centers that have none.
- Build:
  - `lord <name>` changed → rewrite that call's troop argument; a center that had no call gets one added right
    after the existing give_center_to_lord block (before `assign_lords_to_empty_centers`).
  - `lord auto` on a center that had a call → remove that call (the game assigns one).
  - `owner` changed and `lord` left as the old lord whose faction (troop record `faction` field) differs from the
    new owner → treat as `auto` and print in Turkish
    "Praven: lordu King Harlaus (Swadia) yeni sahibe (Vaegirs) uymuyor; oyun bir Vaegir lordu atayacak.
    Kendin seçmek için: lord <ad>".
  - A chosen lord whose faction differs from `owner` → Turkish error with file:line.
- Unchanged project: byte-identical (32/32), exact read-back (12815/12815).
