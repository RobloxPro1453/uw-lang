# T-133: lowering core — values, variables, statements, game start (UW core v0)

Status: ready
Budget: $4.00
Steps: 350

## Goal

`uw_core::lower` turns parsed core files into Native operations (`Lowered`, crates/uw_core/src/lib.rs):
constants, feature variables, object fields, assignments, if/for/let/fn, calls of properties, and
`on game.start`. This is the machinery later tasks (continuous blocks, UI, start flow) build on.

## Known facts

- Spec: docs/dil/CORE-v0.md §1, §4 (fixed-point ×1000, ranges clamp, `var KIND.NAME` = slot above every
  kit slot of that kind, feature vars = `$uw_<feature>_<name>`, `on game.start` appends to `game_start`).
- AST: crates/uw_core/src/ast.rs (fixed). Output types: crates/uw_core/src/lib.rs (`Op`, `Arg`, `Lowered`).
  You may ADD fields/types to lib.rs; do not remove or rename existing ones.
- A parser is written in parallel (T-132); build your test inputs as AST values by hand (a small builder
  helper in the test file), not by parsing.
- Atlas: `target/uw-staging/atlas.json` (constants `slot_agent_*`, `slot_troop_*` … give the used slot
  numbers; ops give names). Load with `uw_atlas::Atlas::from_path`; tests use a tiny inline atlas.
- Native arithmetic is integer: `store_add`, `store_sub`, `store_mul`, `store_div`, `val_add`, `val_clamp`
  (header_operations.py; the kit copy is in your worktree at target/ref/kit/).

## Steps

1. `src/lower/mod.rs` with `pub fn lower(files: &[ast::File], atlas: &Atlas, data: &CoreData) -> Result<Lowered, Vec<Error>>`
   and a public `Ctx` that later tasks extend: `fn expr(&mut self, e: &Expr) -> Result<Arg, Error>` (emits ops
   into the current block, returns where the value is), `fn place_set(...)`, `fn temp() -> Arg` (fresh local),
   `fn slot_for(kind, name) -> i64`, `fn global_for(feature, name) -> String`, `fn begin_block()/end_block() -> Vec<Op>`.
2. `CoreData` loads `kit-meta/core/properties.toml` (create it): each entry maps a path pattern to ops,
   e.g. `player.name` (set) → `troop_set_name trp_player <text>`, `agent.speed` (set) →
   `agent_set_speed_modifier <agent> <percent>`, `player.agent` (get) → `get_player_agent_no <dest>`,
   `key.held(<key>)` (condition) → `key_is_down <key constant>`. Entries are data; the lowering is generic
   (no `match` on property names in Rust).
3. Fixed-point: all UW numbers ×1000; at a property boundary the entry declares the engine's unit
   (`unit = "int"`: divide by 1000; `unit = "percent"`: percent value as is).
4. `var KIND.NAME = v in lo..hi`: allocate slot; every write clamps (`val_clamp`, upper bound exclusive —
   check the op comment). Feature vars → globals, initialised in `game_start` append.
5. `on game.start { … }` → `Lowered.script_appends` for `game_start`.

## How to test

crates/uw_core/tests/lower_core.rs with hand-built ASTs: (a) `var x = 5` + `on game.start { x += 2 }` →
game_start append contains an assign of 5000 and an add of 2000 to `$uw_main_x`; (b) `var agent.stamina = 100
in 0..100` gets a slot number greater than every `slot_agent_*` in the test atlas; a write emits a clamp;
(c) `player.name = "Alex"` emits `troop_set_name` with `trp_player` from properties.toml; (d) an unknown
property is an error with file:line; (e) no property names appear in Rust source (a test greps src/lower for
"speed_modifier" and "troop_set_name" and expects none).

## Done when

- Tests pass; build and tests pass.

## Do not

- Do not edit src/ast.rs, other crates, or write a parser.

## Stop and report if

- A construct of spec §4 cannot be lowered with integer ops (explain).
- A test still fails after 5 steps on it.
