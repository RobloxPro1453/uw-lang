# T-015: Parser — override <id>, new <id>, menu members (text, option, change/remove option)

Status: ready
Budget: $1.50
Steps: 250

## Goal

`uw_syntax::parse` reads the item-level forms of grammar 2 into the AST types that already exist in
`crates/uw_syntax/src/lib.rs`: `Item::Override { kind: None, .. }` for `override menu_x { … }`,
`Item::New`, and `Member::{Text, Option, ChangeOption, RemoveOption}` with `When` and `Place`.

## Known facts

- Spec: `docs/meclis/gramer-2-oneri.md` sections 3, 4 and 7 (examples there are the target syntax).
- `override menu start_phase_2 { … }` (two words) keeps `kind: Some(menu)`; `override menu_start_phase_2 { … }`
  (one word, then `{`) gives `kind: None` and the full id in `name`.
- `new <id> ["text"] { … }`: `text` optional.
- Inside an override / new body: `on <event> { … }` handlers (existing code), `text "…"`,
  `option <id> "<text>" [when <cond> | when { … }] [after <id> | before <id>] { body }`,
  `change option <id> { text "…"  when <cond>|when { … }  do { … } }` (each part optional, any order,
  each at most once), `remove option <id>`. Members are separated like statements (newline or `;`).
- `when {` is always the block form; `when <cond>` uses the existing `Parser::cond` (T-014) and ends at
  the body's `{`. Error messages English and specific (never only "unexpected end of file").

## Steps

1. Extend the item parsing in `parse` (and helpers) for these forms.
2. Unit tests in uw_syntax for each form, both `when` forms, `after`/`before`, a `change option` with
   all three parts, and errors: `option` without text, two `text` parts in one `change option`,
   `when` with nothing after it.
