# T-082: Object words: `player.gold += 1000` (P6)

Status: ready
Budget: $1.50
Steps: 400

## Goal

The easy language's object form works on top of `fn` (T-078): a library defines dotted words and the modder
writes them like fields:

```
fn player.gold.add(:n) { troop_add_gold(trp_player, :n) }
fn player.gold.get(:out) { store_troop_gold(:out, trp_player) }
...
player.gold += 1000        // -> player.gold.add(1000)
player.gold -= 50          // -> player.gold.remove(50)
player.level = 5           // -> player.level.set(5)
if player.gold >= 100 { }  // -> player.gold.get(:_t) before, then :_t >= 100
```

## Known facts

- `fn` parse: crates/uw_syntax/src/lib.rs (`Item::Fn`, T-078); inlining in crates/uw_check/src/lib.rs.
- Assignments are `Stmt::Assign { target, op, value }`; targets today are `$g`, `:l`, register names.
- Lowering temporaries are `:_…` (E0210 forbids users from them).

## Steps

1. Syntax: dotted names (`a.b.c`) as fn names, as assignment targets and as operands in expressions/conditions.
2. Check: `x.y += e` -> call fn `x.y.add(e)`; `-=` -> `.remove`; `=` -> `.set`; a dotted operand -> a fresh
   temporary filled by `x.y.get(:tmp)` placed just before the statement (for `if`/`when`/`require`
   conditions: before the condition's ops). Missing fn: error naming the fn that would be needed.
3. Golden crates/uw_cli/tests/golden/object_words/ with the fns defined in input.uw itself.

## How to test

Golden output fails if any form maps to the wrong fn or the temporary is read before it is filled. Unit
tests for the missing-fn error and for a dotted operand inside `if` and inside `when`.

## Done when

- Build and tests pass; existing goldens unchanged.

## Do not

- Touch lib/**, crates/uw_cli/src/**, crates/uw_decomp/**, kit-meta/**.

## Stop and report if

- Placing the get before a condition is impossible where the condition is lowered. 5 failed steps.
