## What changed

**crates/uw_check/src/lib.rs**
- `copy_table` (`kind` → table) is now a schema lookup: `copy_table(schemas, kind)` returns the `table` of the loaded schema whose `kind == kind` (also matching the table name, because `id_kind` turns `override fac_…` into `factions`). The only literal data left is the required `town|castle|village → parties` alias and a 7-word deny list (`menu`, `dialog`, `script`, `trigger`, `simple_trigger`, `presentation`, `mission_template`) checked against the found schema's `kind`, so those keep their old behaviour. No match on table names anywhere.
- `atlas_with_new_records` now takes `schemas` and passes it to `copy_table`; `check_with_schemas` already had them. The record-override path (`Item::Override`, ~2361) passes the same slice, and the `Item::Like` path (~2988) uses it too. When the kind cannot be resolved (denied word, or no schema at all) the user gets one clear "not in UW yet" diagnostic with help instead of the old silent `continue`.
- Otherwise the paths were already table-agnostic: the schema lookup for fields, the module/var taken from the atlas table, and `record_copy`.

**crates/uw_syntax/src/lib.rs**
- `override <kind> <name>` already accepted any kind. `like` was gated by the fixed `COPY_KINDS` list; added a small lookahead (`<ident> <ident> like`, T-119 comment) so any kind keyword can be parsed as a record copy. The existing `COPY_KINDS` list is kept only so `troop`/`town`… still get their own error message and so `uw_syntax`'s existing loop stays green.
