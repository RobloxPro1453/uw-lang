# T-171: `uw coverage` measures the new language's kit words

Status: ready
Budget: $0.80
Steps: 250

## Goal

`uw coverage` prints one more block, "core language (main.uw projects)", so the owner sees how much of the
engine the NEW language reaches: how many of the kit's 1060 operations the core language can use by name,
and how many of those words lower cleanly against the real atlas.

## Known facts

- The new language's engine words: `uw_core::lower::kit::{kit_ops, kit_properties}` (crates/uw_core/src/lower/kit.rs);
  each `Property` has `path`, `get`/`set`/`cond` steps (`Step { op, args }`), `vector`. Hand-made mechanism
  entries: `uw_core::lower::CoreData::hand_made()`; all together: `CoreData::builtin()`.
- Lowering: `uw_core::lower::lower(&files, &atlas, &data)`; parse with `uw_core::parse` (see
  crates/uw_core/tests/common/mod.rs `parse_files` / `lower_ok` for how tests do it).
- The existing report is crates/uw_cli/src/coverage.rs (`measure`, `Coverage::text`, `Coverage::json`);
  keep its current numbers and lines exactly as they are (other tests read them).
- Real atlas: `target/uw-staging/atlas.json` (tests skip when absent; see crates/uw_cli/tests/coverage.rs).

## Steps

1. In coverage.rs add a `CoreWords` measure: `reachable` = number of distinct Native op names appearing in
   any step of `CoreData::builtin()` properties; `total` = atlas op count; `lowered` = how many kit
   properties lower without error in a one-line probe program against the atlas:
   for an `agent` subject use `player.agent.<name>`; for a property with no `{object}` use `<path>` itself;
   skip other subjects (count them as `skipped`). A getter is probed as `var agent.uw_probe = 0` +
   `while in mission { player.agent.uw_probe = <expr> }`; a setter as `while in mission { <expr> = 1 }`;
   a condition as `while <expr> { }` (empty bodies are fine if the parser accepts them; otherwise put a
   setter of `player.agent.uw_probe = 1` inside).
2. Print after the existing lines: `core language: kit words N, ops reachable R/1060 (P%), lowered L/N, skipped S`
   and add the same numbers to `--json` under `"core"`.
3. Failures: `--all` lists each word that did not lower with its error message.

## How to test

crates/uw_cli/tests/coverage.rs: a new test runs `uw coverage --json` on the real atlas (skip if absent) and
asserts `core.reachable >= 250`, `core.lowered >= core.words * 9 / 10`, and that the old keys are unchanged.
A unit test in coverage.rs checks the probe text for one getter, one setter and one condition.

## Done when

- `uw coverage` shows the core line; build and tests pass.

## Do not

- Do not edit crates/uw_core (report a word that fails to lower instead of fixing the lowering).
- Do not change the existing coverage numbers, weights or lines.

## Stop and report if

- The probe programs do not parse or most words fail for one shared reason: report the reason and stop.
