# T-045: Project folder layout: which file each record goes in (P3a)

Status: ready
Budget: $1.00
Steps: 300

## Goal

`project::layout::path_for` puts each Native record where a modder looks for it: towns, castles and
villages in their own folders, kings/lords/ladies/companions in theirs, one file per rich record, one file
per table for small lookup tables. Decision: docs/arsiv/meclis-yon1-yon2/YON2-KARAR.md §3.2 (file name = Native id, not the
display name).

## Known facts

- File: crates/uw_decomp/src/project/layout.rs (only this file and its tests).
- Range constants are in the atlas: `atlas.ranges` (name, value, line), e.g. `towns_begin`, `castles_begin`,
  `lords_begin`, `kingdom_ladies_begin`, `companions_begin`, `pretenders_begin`, `heroes_begin` and their
  `_end`s. A value may be a number or another constant/id: resolve it against the atlas and VERIFY in
  `Module_system 1.171/module_constants.py` (read-only).
- 27 tables (kit-meta/records/*.toml).

## Steps

1. Rules (use only ranges that exist in the atlas; never invent a range name):
   - parties: `parties/towns/<id>.uw`, `parties/castles/…`, `parties/villages/…`; the rest `parties/<id>.uw`.
   - troops: `troops/kings/`, `troops/lords/`, `troops/ladies/`, `troops/companions/`, `troops/pretenders/`
     by range (only those the kit defines); the rest `troops/<id>.uw`.
   - one file per record: factions, items, party_templates, quests, scenes, scene_props, menus, scripts,
     mission_templates, presentations, map_icons → `<table>/<id>.uw`.
   - dialogs: grouped by the starting dialog state (record field 2) → `dialogs/<state>.uw`.
   - all other tables: one file `<table>.uw` (strings, sounds, meshes, animations, music, skills, skins,
     postfx_params, particle_systems, info_pages, tableau_materials, triggers, simple_triggers).
   - Id = atlas id without the schema prefix; characters unsafe in Windows file names (`: = * ? " < > |`)
     become `_` in the file name only. Two records never share a path unless a rule groups them.
2. Tests: tiny atlas with ranges; real atlas (skip if missing): no two ungrouped records share a path;
   `p_town_6` → `parties/towns/town_6.uw`; print the file count per top folder.

## How to test

The collision test fails if two separate records would overwrite each other; the range test fails if a
town lands outside `parties/towns/`.

## Done when

- Tests green; report the file count per folder on the real atlas.

## Do not

- Touch any file except crates/uw_decomp/src/project/layout.rs (tests inside it or in
  crates/uw_decomp/tests/layout_t045.rs).

## Stop and report if

- A range constant does not resolve to a table index. A test still fails after 5 steps.
