## Goal

`uw_emit::emit` writes the new `Action` variants (crates/uw_check/src/lib.rs: `ReplaceText`,
`InsertOption`, `ChangeOption`, `RemoveOption`, `NewMenu`; today `unimplemented!` in emit) as calls to
these `uw_runtime` helpers (Claude writes the helpers separately; emit only calls them):

```python
game_menus = _uw.set_text(game_menus, ENTRY, 2, TEXT)
game_menus = _uw.add_option(game_menus, ENTRY, 5, (ID, [COND_OPS], TEXT, [CONS_OPS]), after=ID_OR_None, before=ID_OR_None)
game_menus = _uw.change_option(game_menus, ENTRY, 5, ID, text=TEXT_OR_None, condition=OPS_OR_None, consequence=OPS_OR_None)
game_menus = _uw.remove_option(game_menus, ENTRY, 5, ID)
game_menus = _uw.add_entry(game_menus, (NAME, 0, TEXT, "none", [ENTER_OPS], [OPTIONS]))
```

ENTRY, ID, NAME and TEXT are Python string literals made with the existing `py_str`.

## Known facts

- Existing emit code: `wrapper()` writes one `_uw.<func>(...)` call per patch with ops one per line and
  `# origin` comments, values via `value()` / `py_str()`; reuse that formatting for every op list.
  `Op.name` may contain `neg|` / `this_or_next|`: emit it as is (Python bitwise or of kit constants).
- Golden tests in `crates/uw_cli/tests/golden/` need the checker for these forms (parallel task
  T-017), so add emit unit tests in uw_emit that build `Checked` by hand, like the existing ones there.
