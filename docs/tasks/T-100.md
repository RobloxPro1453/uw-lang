# T-100: `uw check [folder] [--json]` — find mistakes without building

Status: ready
Budget: $1.00
Steps: 250

## Goal

`uw check` checks a mod folder or a `uw create` project (parse + check, incl. lib words and names) in a
second or two, without running the kit, and prints the same errors `uw build` prints. `--json` prints one
JSON object per line for editors (T-101 reads it):
`{"file":"<absolute path>","line":3,"column":30,"end_line":3,"end_column":49,"severity":"error","code":"E0001","message":"…","help":"…"}`
and a last line `{"summary":{"errors":N,"warnings":M}}`. Exit code 1 when there are errors.

## Known facts

- Mod folder steps 1-2 (parse, check) are in crates/uw_cli/src/build.rs `run`; projects parse records via
  crates/uw_cli/src/build_project.rs (`load` + `compile_with`). Folder handling and UW-home lookup:
  `cmd_build_any`/`enter_home` in crates/uw_cli/src/main.rs.
- Diagnostics carry spans: crates/uw_diag (`Diagnostic`, `SourceFile`, `render`).

## Steps

1. Factor the parse+check part out of `run` (no behaviour change for `uw build`), and the project
   load/compile part out of build_project, so both are callable without the kit.
2. `check` subcommand (USAGE + dispatch), folder = like `uw build`.
3. Tests: a temp mod folder with one unknown name → `--json` line has the right line/column/code; a clean
   folder → summary errors 0 and exit 0.

## How to test

The JSON test parses each line with serde_json and asserts fields; fails if spans are off by one.

## Done when

- Build and tests pass; `uw build` output unchanged.

## Do not

- Touch crates/uw_syntax, crates/uw_check, lib/**, editors/**.

## Stop and report if

- A project's errors carry no file/line (say where it is lost). 5 failed steps.
