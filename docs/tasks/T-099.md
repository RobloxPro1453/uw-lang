# T-099: New town from an existing one: `town riverhold like praven { }` (easy-language §7)

Status: ready
Budget: $1.50
Steps: 400

## Goal

```
town riverhold like praven {
    name "Riverhold"
    initial_coordinates (35, -12)
}
```
makes a new party record, a copy of Praven with these fields changed, appended at the end of the party
list (Native parties keep their numbers); code can use `riverhold` / `p_riverhold`.

## Known facts

- T-092 did exactly this for troops: `Item::Troop`, `check_with_schemas`, `troop_record`,
  `Action::NewTroop`, uw_emit `add_entry` (crates/uw_syntax, crates/uw_check, crates/uw_emit). Reuse it:
  generalise to a record kind + table (troops, parties) rather than copying.
- Party fields: kit-meta/records/parties.toml. `like` accepts the game name or the bare kit name
  (`praven` or `town_6`), as troops do since d237b95.

## Steps

1. Syntax: `town`, `castle`, `village`, `party` + `<id> like <existing> { … }` all build a parties record.
2. Generalise the troop path; a kind may only copy from its own table (error otherwise).
3. Golden crates/uw_cli/tests/golden/town_like/ (fixture atlas gets Praven's real value if missing).

## How to test

The golden fails if the appended tuple differs; existing troop_like golden unchanged.

## Done when

- Build and tests pass.

## Do not

- Touch crates/uw_cli/src/** (except passing the parties schema like troops), lib/**, kit-meta/**.

## Stop and report if
