# T-078: First words — `fn` written in UW, used like an operation (P6)

Status: ready
Budget: $1.50
Steps: 400

## Goal

A modder (and UW's own library) can name a piece of code once and use it as one line:

```
fn give_gold(:amount) {
    troop_add_gold(trp_player, :amount)
    display_message("@You got gold.")
}
...
give_gold(1000)
```
The call is replaced by the body (inlined) at compile time; the kit sees only Native operations.

## Known facts

- Top-level items: `Item` enum crates/uw_syntax/src/lib.rs:46; item keywords parsed ~:636 (`override`, `new`, `on`).
- Statements: `Stmt::Call(Call)` :100; check walks statements in `stmts` crates/uw_check/src/lib.rs:179;
  `check(atlas, sources, …)` :952 gets all files of the mod, so a `fn` in any file is visible in all.
- Locals are `:name`; `:_…` is reserved for lowering temporaries (E0210 in check).

## Steps

1. Syntax: `fn <name>(:p1, :p2, …) { <block> }` as a new `Item::Fn { name, params, body, span }`.
2. Check: collect every `fn` of all sources first. A `Stmt::Call` whose name is a fn: arity must match;
   replace it by the body with each `:param` replaced by the argument (number, `$global`, `:local`, name,
   text). Other locals in the body are renamed per call site (`:x` -> `:x__fn<N>`) so two calls never share
   them. Calls inside bodies expand too; a cycle or depth > 16 is an error naming the chain.
3. Errors (English like the others, with span): fn name equal to a kit operation; two fns with one name;
   wrong argument count; unknown fn suggestion via the existing unknown-operation message.
4. Golden test crates/uw_cli/tests/golden/fn_words/ (fixture atlas_golden.json): one fn used twice and one fn
   calling another; expected .py shows the inlined operations with distinct renamed locals.

## How to test

Golden output fails if inlining, parameter replacement or local renaming changes. Unit tests in uw_check for
each error (cycle, arity, shadowing an operation, duplicate).

## Done when

- Build and tests pass; existing goldens unchanged.

## Do not

- Touch crates/uw_decomp/**, kit-meta/**, crates/uw_cli/src/** (tests only there).
- Add return values or fn calls inside expressions/conditions (later task).

## Stop and report if

- Inlining needs a change in crates/uw_lower beyond what the expanded statements already lower to.
- A test still fails after 5 steps on it.
