# T-001: uw_diag — diagnostics with line/column and "did you mean"

Status: ready
Budget: $0.60
Steps: 160

## Goal

The compiler can report an error as `error[E0001]: unknown name 'pravn' --> start.uw:3:22` with the
source line, a caret under the span, and `help: did you mean 'praven'?` (finalForm: "wrong name with
line number + did-you-mean suggestion"). All messages are English.

## Known facts

- Crate exists: `crates/uw_diag` (empty `src/lib.rs`, no dependencies). Workspace root `Cargo.toml`.
- No other crate uses it yet. External crates allowed only if MIT/Apache; prefer none.

## Steps

1. `Span { start: usize, end: usize }` (byte offsets, end exclusive) and `SourceFile { name, text }` with
   `line_col(offset) -> (line, col)`, both 1-based; col counts chars (not bytes) so UTF-8 text works.
2. `Diagnostic { code: &'static str, message: String, span: Span, notes: Vec<String>, help: Option<String> }`
   and `render(&SourceFile) -> String` in the shape of the Goal (line, source line, `^^^` under the span).
3. `suggest(name: &str, candidates: impl IntoIterator<Item = &str>) -> Option<String>`: closest candidate by
   edit distance (Damerau-Levenshtein or Levenshtein), only if distance <= max(1, name.len() / 3);
   ties broken by candidate order. Pure function.
4. A small code catalog: `pub const E0001_UNKNOWN_NAME: &str = "E0001";` plus a helper
   `unknown_name(name, span, candidates) -> Diagnostic` that fills `help` from `suggest`.

## How to test

Unit tests in `crates/uw_diag`: `line_col` on multi-line text with a non-ASCII char before the offset;
`render` output compared to an exact expected string (golden string in the test); `suggest("pravn",
["praven","paris"]) == Some("praven")`; `suggest("xyz", ["praven"]) == None`; a tie test. Each test
would fail if the offset math or the threshold were wrong.
