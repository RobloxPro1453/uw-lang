# T-091: `in menu camp { option "Text" { } }` (P6, easy-language §2)

Status: ready
Budget: $1.00
Steps: 300

## Goal

Easy-language example §2 (docs/meclis/kolay-dil-taslak.md) compiles as written:

```
in menu camp {
    option "Party morale report" {
        say("@Morale is fine.")
    }
}
```

## Known facts

- `override menu <name> { … }` and `override menu_<id>` already work (crates/uw_syntax/src/lib.rs `Item::Override`,
  golden examples under crates/uw_cli/tests/golden/). Options today need an id: `option uw_rich "Text" …`.
- Menu ids and the `menu_`/`mnu_`/`mno_` spellings: docs/bilgi/anlam/menuler.md §2.

## Steps

1. Syntax: `in menu <name> { … }` means exactly `override menu <name> { … }`.
2. `option "Text" …` without an id: the id is made from the text (lower case, runs of other characters ->
   `_`, prefixed `uw_`), unique within the menu (`_2`, `_3` …). `when`/`after` keep working.
3. Golden crates/uw_cli/tests/golden/in_menu/ (fixture atlas; add `camp` menu to the fixture if missing).

## How to test

The golden fails if the generated id or the target menu differs. Unit test: two options with the same text
get `uw_x` and `uw_x_2`.

## Done when

- Build and tests pass; existing goldens unchanged.

## Do not

- Touch crates/uw_decomp/**, crates/uw_cli/src/**, lib/**, kit-meta/**.

## Stop and report if
