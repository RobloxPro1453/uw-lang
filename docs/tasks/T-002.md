# T-002: uw_kitrun — Rust port of py/kitrun.py

Status: ready
Budget: $1.00
Steps: 220

## Goal

`uw_kitrun` can make a fresh staging copy of the Module System kit and run its `process_*` steps one
by one with Python 2.7, returning a report — the same behaviour as `py/kitrun.py`, which is the
reference (read it fully first; it was run against the real kit: 29 steps, 0 failures, 32 outputs).

## Known facts

- `py/kitrun.py` functions to port: `kit_files`, `kit_hash`, `steps_from_bat`, `stage`, `run_steps`,
  `outputs`. Same rules: skip `__pycache__` dirs and `*.pyc`; `--no-ids` skips `ID_*.py`; overlay dir
  copied over the kit copy; `module_info.py` rewritten to `export_dir = "<abs staging>/out/"` with
  forward slashes; Python run as `<python> -B -E -s <step>` with cwd = staging and every env var whose
  name starts with PYTHON removed; staging inside the kit is refused.
- Kit at `Module_system 1.171/` (read-only, may be missing on other machines). Python 2.7 at
  `C:\Python27\python.exe` (may be missing). `kit-meta/native.baseline.json` holds the real run's
  `kit_hash` and output sha256s.
- Hashing: sha256; `sha2` crate (MIT/Apache) is fine; `serde`/`serde_json` for the report.

## Steps

1. Public API: `StageOptions { kit, staging, no_ids, overlay: Option<PathBuf> }`, `stage(&StageOptions)
   -> Result<PathBuf /*out dir*/>`, `steps_from_bat(kit)`, `kit_hash(kit)`, `run_steps(staging, steps,
   python) -> Vec<StepResult>`, `outputs(out_dir) -> BTreeMap<String, OutputFile>`, `Report` (serde).
2. Same problem-line regex idea as the Python (case-insensitive words list), no `regex` crate needed.

## How to test

- Unit tests with a fake kit built in a temp dir (`std::env::temp_dir()` + unique name, removed at
  the end): bat parsing order; `__pycache__`/`.pyc` skipped; `no_ids` drops `ID_x.py`; overlay wins;
  `module_info.py` content; `kit_hash` unchanged when only `module_info.py` differs; staging-in-kit error.
- One integration test: if both the real kit and `C:\Python27\python.exe` exist, stage + run all steps
  into a temp dir and assert 0 failed steps and `kit_hash` + every output sha256 equal
  `kit-meta/native.baseline.json`. If either is missing, the test returns early (print why).

## Done when

- Build and tests pass; the integration test really ran on this machine (say so in the report).

## Do not

## Stop and report if

- The integration test's hashes differ from the baseline and you cannot see why in 5 steps.
