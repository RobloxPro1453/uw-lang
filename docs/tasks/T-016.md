# T-016: Lowering — assignments, expressions, if, and/or/not -> Native operations

Status: ready
Budget: $1.50
Steps: 250

## Goal

`uw_lower::lower(&[Stmt]) -> Vec<Op>` (crates/uw_lower/src/lib.rs) lowers `Stmt::Assign` and
`Stmt::If` (today `unimplemented!`) exactly as `docs/arsiv/meclis-yon1-yon2/gramer-2-oneri.md` sections 1, 2, 7 say.

## Known facts

- Op names (header_operations.py lines are in the module doc): `assign`, `store_add/sub/mul/div/mod`
  (dest, a, b), `val_add/sub/mul/div/mod` (dest, x), `eq gt ge lt le neq`, `try_begin`, `else_try`,
  `try_end`; the prefixes `neg|` and `this_or_next|` are written into `Op.name` (`"neg|party_is_active"`).
- In the kit `lt = neg|ge`, `neq = neg|eq`, `le = neg|gt`: NEVER emit `neg|lt`, `neg|neq`, `neg|le`;
  `not` on a comparison flips the operator (`not a < b` -> `ge`).
- Temporaries `:_uw0, :_uw1, ...` (TEMP_PREFIX), numbered from 0 per `lower` call, always written
  before they are read.
- `x = leaf` -> `assign`; `x = a op b` -> `store_<op>(x, a, b)`; nested -> temps; `x += e` ->
  `val_add(x, e)` (e a leaf, else a temp first). Unary minus on a non-literal -> `store_sub(t, 0, e)`.
- Conditions: `And` -> its parts in sequence; an `Or` of single conditions inside an And ->
  `this_or_next|` on all but the last; any other shape -> flag temp: `assign(t, 0)`, then per `or`
  branch `try_begin; <branch>; assign(t, 1); try_end`, then `eq(t, 1)`. `Not` on a non-comparison
  single op -> `neg|op`; on a composite -> flag temp and `eq(t, 0)`.
- `If` -> `try_begin; <cond>; <body>; else_try; <cond2>; <body2>; else_try; <else body>; try_end`.
- Every generated op carries the `origin` of the statement it came from.
