# Engine quirks and workarounds in 17 open-source Warband mods

Topic mining of `#` comments (bug / hack / workaround / crash / doesn't work / fix / careful / WSE / limit) over
`warband-opensource-mods/mods/`. Counts below are mods where the marker/comment was actually found; many mods are
forks and copy the same block, which is itself a finding. Evidence is `mods/<NN-name>/<path>:<line>`.

## Engine facts learned

- Triggers are limited to 3 parameters; extra data must be fetched with the trigger-parameter operations (mods/03-tainted-paths/src/header_operations.py:259).
- `agent_set_division` is reset by the engine as soon as an order is issued to the agent's original division (mods/03-tainted-paths/src/header_operations.py:2532).
- `is_vanilla_warband` is documented as "fails only when WSE is running" (mods/03-tainted-paths/src/header_operations.py:3001); its opcode differs between header generations (998 in mods/07-brytenwalda/source/header_operations.py:2211, 1004 elsewhere).
- `agent_set_item_slot` exists but was removed in WSE 3 (mods/03-tainted-paths/src/module_coop_scripts.py:2085).
- Face-key skin-colour get/set operations (1.161+) "apparently doesn't work" (mods/03-tainted-paths/src/header_operations.py:1045, mods/03-tainted-paths/src/header_operations.py:1047).
- In multiplayer, order operations raise `OPCODE 1785: Invalid Group ID: 1` (mods/03-tainted-paths/src/module_coop_mission_templates.py:328).
- Delivering damage from an agent to itself crashes the game (mods/03-tainted-paths/src/module_coop_mission_templates.py:7511).
- `agent_set_wielded_item` after equipping a flag causes a crash (mods/09-between-empires/SourceCode/module_mission_templates.py:5478).
- `set_shader_param_float` "bugs the game" and must stay disabled (mods/04-medieval-conquests/src/header_operations.py:2120).
- Items spawned with the `itp_attatch_armature` flag produce floating rigging bugs; there is no runtime operation to query that item flag (mods/04-medieval-conquests/src/module_coop_mission_templates.py:2672).
- When the engine recentres the cursor the reported move is not zero, usually about 5 pixels (mods/16-warband-ai-chat/mod_src/module_mission_templates.py:426).
- Trigger delay is inaccurate enough that a 250 ms timer poll is needed instead (mods/07-brytenwalda/source/mission_template_triggers/formations.py:193).
- `*_order_position` operations are buggy for teams 0-3 (mods/08-money-and-honour/src/formations_scripts.py:1087).
- On team reassignment the engine applies the player party's divisions to all agents (mods/08-money-and-honour/src/formations_scripts.py:1755).
- Cavalry in scripted mode will not dismount without clearing scripted mode (mods/08-money-and-honour/src/formations_scripts.py:1444).
- An unwanted engine optimisation keeps showing the old faction banner tableau until the id changes (mods/05-persistent-world/module_constants.py:305).
- Spawned items have engine quirks on a client at mission start, so positions are redrawn then (mods/05-persistent-world/module_constants.py:547).
- `position_rotate_z_floating` is missing; the rotation must be composed from x/y floating rotations (mods/05-persistent-world/module_scripts.py:11163).
- Ground types cannot be added: they are hardcoded in the engine C++ (mods/13-catplomacy/Ground_specs.py:6).
- Alternative speedtree definitions are "NOT FUNCTIONAL in Warband" (mods/13-catplomacy/Flora_kinds.py:158).
- The first items (and their order) are hardcoded in `item_codes.h` and must not be moved (mods/01-anno-domini-1257/module_items.py:434).
- Only reserved or non-hardcoded skill ids may be used for new skills (mods/01-anno-domini-1257/module_skills.py:39).
- Animation sequences are hardcoded; only resources/times can be edited (mods/06-the-last-days/ModuleSystem/module_animations.py:46).
- The "May 31" combat bug returns some defeated heroes in the victorious party too (mods/01-anno-domini-1257/module_game_menus.py:5248).
- Item food-bonus slots decay to 0 for an unknown reason (mods/01-anno-domini-1257/module_simple_triggers.py:6320).
- Quest state transitions can be missed by the engine, leaving quests active (mods/01-anno-domini-1257/module_simple_triggers.py:4671).
- Accessing hard-coded presentations such as the chest crashes the game (mods/11-diplado/source/module_presentations.py:17503, mods/12-beggars-diplomacy/source/module_mission_templates.py:3468).
- A skin must have at least one hair texture, even unused, or the game crashes; large hitbox changes can also crash (mods/06-the-last-days/ModuleSystem/module_skins.py:624, mods/06-the-last-days/ModuleSystem/module_skins.py:630).
- On Warband the `disable_grass` scene flag must be forced in the build script to avoid crashes (mods/06-the-last-days/ModuleSystem/Process/process_scenes.py:51).
- `change_screen_exchange_members` only works from the right context; otherwise a stub menu must be jumped to (mods/06-the-last-days/ModuleSystem/module_dialogs.py:2669, mods/06-the-last-days/ModuleSystem/module_game_menus.py:11090).
- `key_escape` is omitted from `key_clicked` while the command selection is active (mods/06-the-last-days/ModuleSystem/module_mission_templates_form.py:585).
- The Python `add_presentations` merge helper does not work as expected (mods/08-money-and-honour/src/formations_presentations.py:136).
- A register expression (`reg?`) passed into `(script_param, ...)` does not work; it must be stored in a named local first (mods/14-dickplomacy-reloaded/source/c3_scripts.py:423).
- If party morale is not set explicitly it starts at 20 and "seems bugged" (mods/14-dickplomacy-reloaded/source/c3_scripts.py:244).
- A global can end up holding a stale agent id instead of -1 after the hero falls (mods/16-warband-ai-chat/mod_src/module_mission_templates.py:549).
- The engine can return an out-of-range item id, so guards like `(is_between, ":item", 1, "itm_items_end")` are needed (mods/01-anno-domini-1257/module_mission_templates.py:1704).
- `agent_set_speed_limit` affects AI only, not player-controlled agents (mods/15-economy-mod/Module_system 1.134/header_operations.py:757).
- Some operations are only valid inside an item trigger; `cur_item_add_mesh` is documented as usable only in `ti_on_init_item` (mods/09-between-empires/SourceCode/header_operations.py:1018).
- Engine changes made a presentation that used to be started at normal banner selection crash; it has to be moved to a world-map simple trigger (mods/02-twilight-of-the-sun-king/module_presentations.py:13601).
- A buggy mission template is simply disabled with a comment instead of fixed (mods/04-medieval-conquests/src/module_coop_mission_templates.py:1075).

## Pain points

- The same native bug note and workaround is copy-pasted into many forks; there is no shared compatibility library, so a fix has to be re-found and re-applied 10+ times.
- Magic numbers are the API: 250 ms timer polls, 10-pixel mouse epsilon, `90 * 1000000` rotations, 50 idle cycles, `-1` sentinels.
- Most workarounds are prose plus a disabled line; nothing type-checks that the engine really behaves that way, and a comment is the only regression test.
- Engine state is silently corrupted (divisions reset, food slots decay, quests stay active, globals hold stale ids), so mods need permanent repair triggers that cost CPU every game hour.
- Hardcoded tables force edits to generated/engine-owned files; a wrong item or animation order is a crash, not a compiler error.
- Version and extension differences (vanilla vs WSE, 1.134 vs 1.151 vs 1.171 header opcodes) multiply branches and duplicate operations.
- There is no way to ask the engine what exists at runtime: whether an operation is available, whether an item has a flag, or how many parameters a trigger accepts must be known from comments.
- Crash-prone operations are only discoverable by trial; the usual "fix" is to comment the line and leave a warning for the next modder.

## For UW

- Give engine limits a first-class place: trigger arity, hardcoded id ranges and per-mode opcode availability should be compiler knowledge, never comments.
- Generate timer polling (`after`, `wait`, `every`) from a safe primitive so users never hand-roll mission-timer arithmetic or trust trigger delay.
- Offer declarative "repair" rules for engine-decayed state, compiled into periodic repair triggers automatically.
- Treat known-crashing operations as compile errors with a safe alternative, instead of letting a commented-out line carry the knowledge.
- Provide capability/version detection (`has_extension`, `version`) as a normal condition and emit the required guards automatically.
- Hide hardcoded table constraints behind checked declarations and reject reordering or extension at compile time with a clear diagnostic.
- Expose events such as "cursor recentred", "agent division reset" or "UI cache invalidated" as general verbs; keep epsilon values in one standard library place.
- Replace raw slots/registers with typed fields and sentinel-free option types, so stale ids and slot aliasing cannot silently corrupt state.
- Let the compiler prove that an operation is used in the right context (presentation, item trigger, MP) and explain the restriction when it is not.
