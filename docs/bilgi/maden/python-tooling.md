# Python-side tooling of the Module System (build scripts, processors, generators, macros)

Corpus: the 17 mods under `warband-opensource-mods/mods/`. This file only looks at the **Python/compiler side**
(build entry points, `process_*.py` changes, header extensions, code generators, helper functions that expand into
operation lists) and not at gameplay op lists. Evidence form: `mods/<NN-name>/<path>:<line>`.
Names used below are Python-side names (files, functions, module-level lists), never guessed engine names.

## Engine facts learned

- **An operation takes at most 16 parameters.** The processor raises its own error with that number when a tuple is
  longer, so the writer had to learn the cap the hard way (`mods/05-persistent-world/process_operations.py:191-192`).
- **A script body has at most 128 local variables**; past that the compiler only warns and the engine truncates
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:459-460`,
  `mods/09-between-empires/SourceCode/compiler.py:747-748`).
- **Only 16 skins exist** and the build refuses more: `the maximum number of skins is 16`
  (`mods/05-persistent-world/process_skins.py:5-7`).
- **A game menu has 16 option slots**, three of which are needed for next/previous/back, hence the hand-written
  "never more than 13 per page" rule (`mods/01-anno-domini-1257/template_tools.py:41-43`).
- **Scripts that can fail must be named `cf_`**: a can-fail op at nesting depth 0 makes the whole script fail at
  runtime, so the compiler warns when the name or a called script does not say `cf_`
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:444-448`,
  `mods/05-persistent-world/process_operations.py:222-226`).
- **`store_script_param_1` / `_2` should be read once**: the build warns when the same parameter is fetched twice
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:450-453`).
- **`try_begin`/`try_end` must balance inside a block**; an unbalanced count corrupts the block length written in
  front of it, so the compiler counts depth and aborts (`mods/05-persistent-world/process_operations.py:242-248`,
  `mods/17-nmc-enhanced-module-system/process files/process_operations.py:432-439`).
- **Global variable and quick-string numbers are part of the save data**, which is why the build caches them in
  `variables.txt` / `quick_strings.txt` next to the exported .txt files and re-loads them
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:121-145`,
  `mods/05-persistent-world/process_operations.py:52`).
- **The first entries of several record lists are reserved**: the unused-object report has to skip the first
  strings/items/troops when reporting, i.e. the engine owns those slots
  (`mods/17-nmc-enhanced-module-system/process files/process_tags_unused.py:17-18`,
  `mods/17-nmc-enhanced-module-system/process files/process_tags_unused.py:38-39`).
- **Faction relations are a full symmetric matrix**; only one direction is authored and the build mirrors it
  (`mods/10-persistent-kingdoms/process_factions.py:7-16`).
- **The item list ends with a dummy terminator record** that must stay last; the merge tool has a dedicated
  pop/push special case for it (`mods/08-money-and-honour/src/modmerger.py:108-128`).
- **Some .txt headers repeat the record count** (`parties: "<n> <n>"`, per-record member count) and several fields
  are written twice from one module field, so the writer has to keep duplicated numbers in sync
  (`mods/10-persistent-kingdoms/process_parties.py:5-7`,
  `mods/10-persistent-kingdoms/process_parties.py:15-17`).
- **Records have optional trailing fields**: `entry[2]` may be a single id or a `(id, flags)` block, and
  `entry[11]` may be absent, so the serializer defaults them (`mods/10-persistent-kingdoms/process_parties.py:10`,
  `mods/10-persistent-kingdoms/process_parties.py:19`).
- **The compiled files carry no type or parameter metadata**, only opcode numbers; the compiler therefore keeps
  its own tables of which op writes its first argument and which can fail
  (`mods/17-nmc-enhanced-module-system/header files/header_operations.py:1618-1627`,
  `mods/17-nmc-enhanced-module-system/header files/header_operations.py:1629`).
- **Troop skill flags are a packed integer**: four bits per skill, value in the low nibble, so `knows_<skill>_<n>`
  is `n << (skill_index << 2)` (`mods/03-tainted-paths/src/header_skills.py:551-560`).

## Pain points

- **Every mod owns a forked compiler.** 14 mods ship their own `process_*.py` tree; the same function sits at
  `process_operations.py:144` in one copy and at `:151`/`:160` in another
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:144`,
  `mods/03-tainted-paths/src/process_operations.py:151`). Fixes cannot reach the other copies.
- **The same three helper scripts are copy-pasted 11-12 times** (unused report, re-indenter, unused globals); the
  copies already drift in line numbers and in the skipped reserved indices.
- **Diagnostics are printed guesses.** The build runner special-cases `TypeError`/`SyntaxError` text and tells the
  author to look for a missing comma or bracket
  (`mods/05-persistent-world/build_module.py:162-178`) instead of pointing at a file and line.
- **Debugging the output means decoding numbers.** The only bridge is a hand-written script that maps an opcode from
  an error message back to a name (`mods/05-persistent-world/print_opcode_name.py:6-10`), plus print-by-index
  scratchpads (`mods/01-anno-domini-1257/dosomethingsomething.py:15-18`).
- **Positional tuples are the schema.** Party, item, menu and troop fields are read by index, some written twice
  (`mods/10-persistent-kingdoms/process_parties.py:15-17`); one inserted field silently shifts the .txt layout.
- **Variable/slot numbers leak into saves**, so authors add caches, "never used" reports and "unassigned local"
  errors by hand to protect them
  (`mods/17-nmc-enhanced-module-system/process files/process_operations.py:296-298`).
- **Grafting another mod means string surgery.** The two responses in the corpus are a merge framework with
  in-memory list wrappers (`mods/08-money-and-honour/src/modmerger.py:88-97`) and a marker-comment installer that
  rewrites source files (`mods/08-money-and-honour/src/modmerger_installer.py:85-97`); both exist because there is
  no composition primitive.
- **Python 2 only.** Tools rely on `print` statements, `xrange`, tuple `except ValueError, IndexError` and
  `__import__(..., -1)`; W.R.E.C.K. refuses to start on Python 3 at all
  (`mods/08-money-and-honour/src/modmerger.py:71`, `mods/09-between-empires/SourceCode/compile.py:4-5`).
- **Speed**: the old batch pipeline started the interpreter once per file, which is why 06 replaced it with a single
  importing driver (`mods/06-the-last-days/ModuleSystem/Process/process_all.py:1`).
- **No tests anywhere.** Verification is "the build ran"; the only checks are the ad-hoc passes listed above.

## For UW

1. Generate the build pipeline from declarations: no vendored compiler copies, no per-mod `process_*.py` forks; a
   build is one command over the project model.
2. Make macros a first-class verb: a function that takes typed ids and returns a statement list, with compiler-owned
   temporaries, instead of hand-allocated scratch locals and splice hooks.
3. Treat constants as expressions, fold them late, and report what is unused or unresolved as diagnostics with
   source spans, not as printed warnings after the fact.
4. Expose record fields by name (`trp.<id>.<field>` style) in the language itself, with optional trailing fields and
   real defaults, so no source ever indexes a tuple positionally.
5. Own the numeric ids: keep them stable, warn on reordering, and migrate cached id tables automatically.
6. Publish the engine's limits as checked facts (parameters per operation, locals per block, skins, menu options,
   one-read parameters) and fail at the declaration, not after export.
7. Emit the derived tables automatically (relation matrices, string/file tables, per-state counts) instead of asking
   every project to write a callback pass.
8. Ship the introspection tools (opcode names, id dumps, usage reports) as a general verb of the compiler, since the
   language is high level but the .txt files stay low level.
9. Make composition a language feature: add-ons declare requirements and extend entity types; consumer projects do
   not patch each other's sources.
